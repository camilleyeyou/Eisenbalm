## Spacing Scale

Declared values (multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon-to-label gaps, badge inner padding |
| sm | 8px | Stacked field spacing, compact button padding |
| md | 16px | Card inner padding, form group gaps |
| lg | 24px | Section vertical rhythm, card-to-card gaps |
| xl | 32px | Layout main-content padding |
| 2xl | 48px | Page-level section breaks (e.g. between Run Control and Budget sections on Config page) |
| 3xl | 64px | Not used in this phase — operator dashboard is dense |

**Exceptions:** 44px minimum touch/click target height on all interactive controls (kill-switch toggle, Trigger Run button, Cancel button, Re-roll buttons). Apply `min-h-[44px]` on every `<button>` — consistent with established Phase 21–24 pattern (`AppSidebar.tsx` line 38).

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#ffffff` (`--background`) | Page background, card surfaces |
| Secondary (30%) | `#f5f5f5` (`--secondary` / neutral-50) | Table header rows, sidebar, muted panels, disabled states |
| Accent (10%) | `#171717` (`--primary` / neutral-900) | Active nav, primary CTA button background ("Trigger Run"), focus rings |
| Destructive | `#ef4444` (`--destructive`) | Cancel run button, kill-switch OFF state visual indicator, budget-cap breach alert border |

**Accent reserved for:** "Trigger Run" button background · active sidebar nav item · focus-visible ring (`ring-neutral-900`) · kill-switch toggle thumb when ON. NOT used for decorative elements or secondary actions.

**Kill switch OFF state:** When `schedule_enabled = false`, the kill-switch toggle uses `bg-red-500` background (not `--primary`) and shows a red badge labeling the state "Automation OFF" in `text-red-700`. This is the ONLY element in the dashboard with a red background in non-destructive context — justified because "automation is disabled" is a high-urgency operational state the operator must not miss.

**Budget alert surface:** When month-to-date spend crosses the alert threshold, an amber warning banner (`bg-amber-50 border-amber-200 text-amber-800`) appears at the top of the Runs page, above the trigger button. This is informational, not destructive.

**Status badge palette (pre-existing, extend with `cancelled`):**

| Status | Background | Text |
|--------|-----------|------|
| running | `bg-blue-100` | `text-blue-800` |
| done | `bg-green-100` | `text-green-800` |
| failed | `bg-red-100` | `text-red-800` |
| awaiting-review | `bg-yellow-100` | `text-yellow-800` |
| cancelled | `bg-neutral-100` | `text-neutral-600` |

**Source:** `RunsTable.tsx` STATUS_CLASSES (lines 39–44). Add `cancelled` entry. Use `neutral` (not red) for cancelled — it is a deliberate operator action, not a failure.

## Component Inventory

### New surface: Run control header (Runs page)

Add a control bar above the existing `CostRollup` + `RunsTable` on `/runs`. Layout: flex row, `justify-between`, `items-center`.

**Left:** Page heading `<h1>` (unchanged — "Runs")
**Right:** "Trigger Run" button — primary, `min-h-[44px] px-4`, neutral-900 background with white text. Disabled + tooltip "A run is already in progress" when a run has `status === 'running'` (D-12 block-with-explanation).

Budget alert banner (conditionally rendered above the control bar): single-row `bg-amber-50 border border-amber-200 rounded-md px-4 py-3 text-sm text-amber-800` with an amber `AlertTriangle` lucide icon (16px) and the copy from the Copywriting Contract below. Dismissible with an `X` button (icon-only, aria-label "Dismiss budget alert", `min-h-[44px] min-w-[44px]`).

### Trigger Run confirmation flow (inline — no modal)

When the operator clicks "Trigger Run":
1. Button changes to "Confirm Run?" with secondary styling + a "Cancel" text link alongside.
2. Operator clicks "Confirm Run?" → POST `/pipeline/run` → button reverts to "Trigger Run" disabled while running.
3. Operator clicks "Cancel" → revert to idle state with no network call.

This is NOT a modal dialog. Inline two-step confirmation is consistent with the Phase 24 block-with-explanation pattern (no queue, no optimistic UI before the user confirms).

### New surface: Cancel run (Run detail page)

On `/runs/[runId]`, below the Run header card, add a "Cancel Run" button when `run.status === 'running'`. Styling: `bg-white border border-red-200 text-red-600 hover:bg-red-50 min-h-[44px] px-4 rounded-md text-sm font-medium`.

Two-step inline confirmation (same pattern as Trigger Run):
1. Click → button becomes "Confirm Cancel?" + "Keep Running" text link.
2. Confirm → POST `/runs/{id}/cancel` → run status badge updates via Convex subscription.
3. Dismiss → revert.

Idempotent: if `run.status` is already `cancelled`, `done`, or `failed`, the Cancel button does not render.

### New surface: Re-roll agent section (Run detail page)

On `/runs/[runId]`, add a "Re-roll" button per row in the Per-Agent table, rendered only for section-writer agents (`origin_story`, `problem`, `founder_bio`, `case_study`, `game`, `bonus`, `design`). Non-section agents get no button in that column.

Button: `text-xs text-neutral-500 hover:text-neutral-900 underline` (text link style, not a filled button — low-prominence because re-roll is an infrequent operation).

Disabled state: when `run.status === 'running'`, button shows "Re-roll" grayed (`text-neutral-300 cursor-not-allowed`) with tooltip "Available after run completes (D-04)".

One-step confirmation: clicking "Re-roll" opens a `window.confirm()` dialog ("Re-roll [section name]? This will regenerate just this section and rewrite the Sanity draft."). If confirmed → POST `/runs/{id}/agents/{key}/rerun` → on success, a `text-green-600 text-xs` inline "Re-rolled ✓" message appears for 3 seconds beside the button.

### New surface: Config page — three panels

The `/config` page is rebuilt from placeholder to three stacked panels. Existing placeholder (`ConfigPage`) is replaced entirely.

**Panel 1 — Automation (kill switch + schedule):**
Card: `rounded-lg border border-neutral-200 bg-white p-5`
Header: `<h2 class="text-base font-semibold text-neutral-900">Automation</h2>`

Kill switch row:
- Label: "Scheduled runs" (text-sm font-medium text-neutral-700)
- Toggle: `<button role="switch" aria-checked={scheduleEnabled}>`; when ON: `bg-neutral-900 text-white`; when OFF: `bg-red-500 text-white`
- Status badge: "Automation ON" (`text-neutral-600 bg-neutral-100`) or "Automation OFF" (`text-red-700 bg-red-50 border border-red-200`), always visible beside the toggle
- Minimum 44px click target on toggle

Schedule editor (visible only when `scheduleEnabled === true`, collapsed/hidden when OFF — no reason to edit a cadence that won't fire):
- Day of week: `<select>` with Mon–Sun options
- Time (UTC): hour + minute selects
- "Next run:" display line below inputs, in operator local timezone with UTC alongside (D-11): `"Next run: Thu Jun 26, 2:00 PM PDT (21:00 UTC)"`
- Save button: "Save Schedule" — secondary styling, min-h-[44px]

**Panel 2 — Budget Caps:**
Card, same styling as Panel 1.
Header: `<h2>Budget Caps</h2>`

Two number inputs:
- "Per-run cap (USD)" — `type="number" min="0" step="0.01"` — reads `per_run_cap_usd` from `pipeline_config`; placeholder "e.g. 10.00"
- "Monthly cap (USD)" — `type="number" min="0" step="0.01"` — reads `monthly_cap_usd`

Alert threshold row:
- "Alert threshold (%)" — `type="number" min="50" max="100"` — reads `alert_threshold_pct`; helper text "Alert fires when month-to-date spend reaches this % of monthly cap"

Save button: "Save Caps" — secondary styling, min-h-[44px]

Trailing-average projection display (read-only, below the inputs):
- "Projected next run cost: $X.XX" (4-decimal, trailing avg of last 4 completed runs)
- "Month-to-date: $X.XX of $Y.YY cap" (progress bar: `bg-neutral-200 rounded-full h-1.5` track; fill = `bg-amber-400` when ≥ threshold, `bg-neutral-400` otherwise)
- If no cost history: "No completed runs yet — projection unavailable"

**Panel 3 — Danger Zone:**
Card with `border-red-200` border (not `border-neutral-200`).
Header: `<h2 class="text-base font-semibold text-red-700">Danger Zone</h2>`
Content: Copy-only entry point — "To force-cancel a running run, go to Runs and click Cancel on the active run." (text-sm text-neutral-600). No additional destructive actions in this panel in this phase.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA | "Trigger Run" |
| Trigger confirmation step | "Confirm Run?" |
| Trigger cancel step | "Cancel" (plain text link) |
| Run already active (tooltip / inline) | "A run is already in progress. Wait for it to complete or cancel it first." |
| Cancel run button | "Cancel Run" |
| Cancel confirmation step | "Confirm Cancel?" |
| Cancel dismiss step | "Keep Running" |
| Re-roll button | "Re-roll" |
| Re-roll confirm dialog | "Re-roll [section name]? This will regenerate just this section and rewrite the Sanity draft. All other sections are unchanged." |
| Re-roll success inline | "Re-rolled ✓" (3 seconds, then cleared) |
| Re-roll disabled tooltip | "Re-roll is available only after the run completes (D-04)." |
| Kill switch ON label | "Automation ON" |
| Kill switch OFF label | "Automation OFF" |
| Schedule section heading | "Automation" |
| Budget section heading | "Budget Caps" |
| Next-run display | "Next run: {Day} {Month} {D}, {H}:{MM} {TZ} ({HH}:{MM} UTC)" |
| Budget alert banner | "Month-to-date spend has reached {N}% of your monthly cap (${X} of ${Y}). Add capacity or pause automation." |
| No cost history | "No completed runs yet — projection unavailable. Per-run cap applies." |
| Start-gate refusal | "Projected cost would exceed the monthly cap (${X} MTD + ${Y} projected > ${Z} cap). Raise the cap or wait until next month." |
| Empty runs history | "No pipeline runs recorded yet. The first run will appear here once the dispatch pipeline is triggered." |
| Empty state config projection | "No completed runs yet — projection unavailable." |
| Error loading data | "Unable to load data. Check your connection and refresh." |
| Re-roll non-section 422 | "This agent is not re-rollable. Only section writers can be re-rolled (origin story, problem, founder bio, case study, game, bonus, design)." |

**Copywriting rules (inherited from CONTEXT.md + brand brief):**
- No exclamation marks
- No urgency vocabulary ("hurry", "now", "immediately")
- Dry, operational register — operator tools copy is declarative, not marketing
- Error copy = problem description + next step (never bare "Error")
- Destructive actions always name the exact operation ("Cancel Run", "Re-roll origin_story")

## Interaction States

Every interactive control must implement all five states:

| State | Visual treatment |
|-------|-----------------|
| Default | Neutral styling per component spec above |
| Hover | `hover:bg-neutral-50` (secondary) or `hover:bg-neutral-800` (primary) |
| Focus | `focus-visible:ring-2 focus-visible:ring-neutral-900 focus-visible:ring-offset-1` — inherited from AppSidebar pattern |
| Disabled | `opacity-50 cursor-not-allowed` — remove hover effect |
| Loading | Replace button label with a `<span>` containing an `animate-spin` 16px `Loader2` lucide icon + sr-only "Loading…" text; disable the button |

Loading state applies to: "Trigger Run" while POST is in flight, "Confirm Cancel?" while cancel POST is in flight, "Save Schedule" while config PUT is in flight, "Save Caps" while caps PUT is in flight.

## Accessibility Contract

| Requirement | Implementation |
|-------------|---------------|
| ≥44px touch targets | `min-h-[44px]` on every `<button>` — inherited from Phase 21 pattern |
| Focus-visible ring | `focus-visible:outline-none focus-visible:ring-2 focus-visible:ring-neutral-900 focus-visible:ring-offset-1` on all interactive elements |
| Kill-switch toggle | `role="switch"` + `aria-checked={boolean}` + visible state label ("Automation ON/OFF") beside it — never status communicated by color alone |
| Budget alert banner | `role="alert"` so screen readers announce it on appearance |
| Re-roll dialog | `window.confirm()` is accessible by default on all browsers; no custom modal needed for this low-frequency action |
| Inline confirmation sequences | Focused on "Confirm" button after primary button click (via `autoFocus`) so keyboard users don't re-tab |
| Loading state | `aria-busy="true"` on button + `aria-label="Loading, please wait"` |
| Single `<main>` | Dashboard layout already has a single `<main>`; no new `<main>` added |
