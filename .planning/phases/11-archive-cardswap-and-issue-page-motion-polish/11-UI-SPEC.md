## ARC-01: CardSwap Component

### Location

New component: `apps/web/components/archive/CardSwap.tsx` ('use client').
Integrated into `apps/web/app/archive/page.tsx` above the existing `<ArchiveList>`.
The existing `ArchiveList` is preserved and still renders below (or in the
reduced-motion fallback, it is the only view).

### Data binding

Binds to the existing `ArchiveIssue[]` array already fetched by the archive
page's `QUERY_ARCHIVE` server component. No new GROQ query. No additional Sanity
fetch. CardSwap receives `issues: ArchiveIssue[]` as a prop.

From `ArchiveIssue`, CardSwap reads: `issueNumber`, `publishDate`, `slug`,
`charity.name`, `charity.focusArea`, `charity.assetRange`, and `bonusType`.
It does NOT read `charity.location` or `charity.slug` (available but not
displayed in the compact card format).

**Read time** is NOT in `ArchiveIssue` (it requires section body word counts,
available only in the full issue query `QUERY_ISSUE_BY_SLUG`). The CardSwap card
displays `charity.focusArea` and `charity.assetRange` instead of read time.
This is a deliberate design decision — the archive card is a preview, not a
replica of the full hero meta row.

### Geometry (researcher design decisions within CONTEXT.md constraints)

| Property | Value | Rationale |
|----------|-------|-----------|
| Container size | 500px wide × 400px tall (max-w-full) | CONTEXT.md reference values |
| CSS perspective | 1200px on the `.cardswap-scene` parent | Enough depth without extreme foreshortening |
| Card distance (depth offset) | 50px per z-step | CONTEXT.md reference |
| Vertical distance (y-offset per stacked card) | 18px | Keeps stack tight, readable on mobile |
| Rotation angle per stacked card | 2deg around X-axis | Subtle tilt suggesting a physical deck |
| Number of visible cards | 3 (front + 2 behind) | More than 3 clips below container bottom |
| Auto-advance timer | 6000ms | CONTEXT.md reference |
| Transition duration (card advance) | 500ms | Responsive feel, not jarring |
| Transition easing | `cubic-bezier(0.34, 1.56, 0.64, 1)` | Approximates elastic easing as per CONTEXT.md decision; no GSAP required |
| Pause on hover | yes — `clearInterval` on `mouseenter`, restart on `mouseleave` | CONTEXT.md ARC-01 |

**CSS 3D implementation:**
- `.cardswap-scene`: `perspective: 1200px; position: relative;` width × height as above.
- Each `.cardswap-card` gets: `position: absolute; width: 100%; height: 100%; transform-style: preserve-3d; transition: transform 500ms cubic-bezier(0.34,1.56,0.64,1), opacity 500ms ease;`.
- Front card (index 0): `transform: translateZ(0) rotateX(0deg); opacity: 1;`
- Card at index 1: `transform: translateZ(-50px) translateY(18px) rotateX(2deg); opacity: 0.55;`
- Card at index 2: `transform: translateZ(-100px) translateY(36px) rotateX(4deg); opacity: 0.35;`
- Cards behind index 2: `opacity: 0; pointer-events: none;` (hidden but in DOM).
- On advance, the front card exits with a brief upward lift (`translateY(-20px) translateZ(20px)`) before being moved to the back of the DOM order via `useState` index cycling.

**No CSS classes to add to globals.css for card geometry** — all transform
values are applied as inline `style` props from the component (calculated from
card index). The component uses `--color-*` tokens for colors and reuses the
existing `.section-card` hover glow by applying the same CSS custom properties.

### Indicator dots

Rendered as a row of `<button>` elements below the card stack. Each button:
- Visible element: 8px circle (active) or 3px circle (inactive) via `width/height` toggle.
- Hit area: `min-w-11 min-h-11` (`44px`) with flexbox centering of the visible dot inside.
- `aria-label="Issue {issueNumber}"` on each button.
- `aria-current="true"` on the active dot.
- Active color: `--color-primary`. Inactive: `--color-text-mute` at 50% opacity.
- Keyboard: Enter/Space activates that card.

### "N issues" badge

Rendered above the card stack, aligned right.
- Text: `{issues.length} ISSUES` (e.g., "14 ISSUES").
- Badge: `--color-primary` text; `color-mix(in srgb, var(--color-primary) 14%, transparent)` bg; 1px `--color-line-strong` border; 2px border-radius; 9px ui font, 500 weight, 0.1em letter-spacing.

### Click to open

The front card is a `<a href="/issue/{slug}">` link (not a `<button>`). Clicking
navigates to the issue. The component wraps the `<a>` so that the indicator
dots and prev/next controls are siblings, not children of the link.

The prev/next controls are optional icon `<button>` elements (chevron left/right
from lucide-react) rendered at the left/right edges of the card stack. Min 44px
touch target. `aria-label="Previous issue"` / `"Next issue"`.

### Reduced-motion fallback (LOCKED constraint)

Under `prefers-reduced-motion: reduce`:
- `CardSwap` renders nothing (returns `null` or a `display:none` wrapper). The
  existing `ArchiveList` below is the full accessible view.
- Alternatively, the CardSwap renders a static single-card view with no
  auto-cycle and no transition. The indicator dots still render and are keyboard-
  navigable to jump between cards (instant swap, no transition).

**Recommended implementation:** Use `window.matchMedia('(prefers-reduced-motion: reduce)').matches`
at mount. If true: skip auto-advance timer entirely; set all card CSS
transitions to `none`; keep indicator dots functional (instant swap on click).

### Print behavior

`.cardswap` wrapper has `data-print-hide="true"`. The existing print
stylesheet's `[data-print-hide="true"] { display: none !important; }` rule
already handles this.

## MOT-01: IssueHero Clip-Path Reveal

### What changes

`apps/web/components/issue/IssueHero.tsx` is modified to add a line-by-line
clip-path reveal on the charity name (`<h1>`). The rest of the component
(ghost numeral, eyebrow, mission, meta row, PDF link) is unchanged.

### Interaction spec

The `<h1>` charity name is split into one `<span>` per line-break word group.
Each span starts with `clip-path: inset(0 0 100% 0)` (clipped from bottom —
fully hidden) and `transform: translateY(12px) opacity: 0`.

On mount (or on `DOMContentLoaded`), spans are revealed sequentially:
`clip-path: inset(0 0 0% 0)` + `transform: translateY(0)` + `opacity: 1`.

**Duration:** 600ms per span.
**Stagger:** 80ms between spans.
**Easing:** `cubic-bezier(0.4, 0, 0.2, 1)` (standard ease-out).

**Implementation note:** Since charity names vary in length, "lines" are
approximated by splitting on every word (one `<span>` per word) rather than on
visual line breaks. Each word-span reveals left-to-right top-to-bottom in
DOM order. This avoids needing ResizeObserver to detect line breaks.

**CSS-only approach (no JS):** The stagger can be implemented purely with CSS
`animation-delay` on each `<span>` using `nth-child(N)` selectors for up to 8
words. The component generates `style={{ animationDelay: '{n * 80}ms' }}` inline
per span. No IntersectionObserver needed (hero is always above the fold).

### Reduced-motion behavior (LOCKED)

Under `prefers-reduced-motion: reduce`: The existing globals.css guard sets
`animation-duration: 0.01ms !important`. No additional JS guard is needed —
the CSS animation fires but completes in ~0ms, making the content immediately
visible. This satisfies the CONTEXT.md constraint: "instant reveals."

The `clip-path` initial value must NOT be set in a way that leaves content
invisible if animation does not run. Correct approach: set `clip-path` only via
the animation's `@keyframes from {}` block (not as a default style), so the
element starts visible and the animation overrides it. Under reduced-motion, the
guard collapses the animation to near-zero duration and the final `to {}` state
applies immediately.

**Critical:** the `<h1>` word-spans must never have `opacity: 0` as a base
(non-animated) default. Opacity is only applied as part of the animation
keyframes.

### No new globals.css addition for hero

Define the `@keyframes heroWordReveal` animation inline in the component file
using Tailwind's arbitrary animation or a `<style>` tag scoped to the component.
Do not add to globals.css (too specific to one component).

### What changes

### Interaction spec

```css
transform: translateY(-4px);
```
Combined with the existing `box-shadow` on hover, this gives a card "lift"
effect. The `transition` on `.section-card` already includes `transform 0.3s`.

**This is a CSS-only change** — one new value in the existing `.section-card:hover`

### Reduced-motion behavior (LOCKED)

`transition-duration: 0.01ms !important`, so the translate applies instantly on

No JS is added for MOT-02. The magnetic glow JS (mousemove → --mx/--my) already
has its reduced-motion early-return in `SectionNavigator.tsx`.

### Touch targets

The existing `.section-card` has `min-height: 200px` which already far exceeds
44px. The hover translate does not change the hit area.

## MOT-03: Deliberation Confidence Count-Up + Pitch-Card Scroll-Snap

### What changes

`apps/web/components/issue/DeliberationSlot.tsx` is modified in two places:
1. Confidence meter value animates 0→real-value on scroll-into-view.
2. Pitch-card list becomes a scroll-snap carousel.

The existing Convex subscriptions, DEL-04 no-model-names rule, live `useQuery`
hooks, and all deliberation content are NOT modified.

### MOT-03a: Confidence count-up on scroll-into-view

**Current state:** The confidence meter renders the final value immediately
(static). The fill bar already has a `width` transition.

**New behavior:** When the deliberation `<section>` scrolls into view (using
`IntersectionObserver`), the displayed percentage value animates 0→`editorConfidence * 100`
over 1200ms. The bar fill width also transitions from `0%` to the real width
(the existing `transition: 'width 0.6s ease'` on the fill div is sufficient,
but the `width` style should start at `0%` and update after the intersection
fires).

**Count-up implementation:**
- `useRef` on the confidence meter section.
- `IntersectionObserver({ threshold: 0.4 })` — fires when 40% of the section
  is visible.
- JS counter: `requestAnimationFrame` loop from 0 to `Math.round(editorConfidence * 100)` over 1200ms, updating `useState(displayedValue)`.
- Easing: linear (simpler, reads as a meter filling up).
- One-shot: once fired, observer is disconnected.

**Reduced-motion behavior (LOCKED):**
Under `prefers-reduced-motion: reduce`: Skip the count-up animation entirely.
JS early-return using `window.matchMedia('(prefers-reduced-motion: reduce)').matches`.
Set `displayedValue` directly to `Math.round(editorConfidence * 100)` and set
bar width to final value. The IntersectionObserver still fires (to set the
final value), but the rAF loop is skipped.

**Critical:** The displayed confidence value must NOT stay at `0` if
reduced-motion is set. The observer still runs; it just skips animation and
sets the final value immediately.

### MOT-03b: Pitch-card scroll-snap carousel

**Current state:** Pitch cards render in a `flex-col gap-4` vertical list in
the left column.

**New behavior:** On mobile and tablet (< 960px, where the two-column layout
collapses to single column), the pitch-card container becomes a horizontal
scroll-snap container:
```css
display: flex;
flex-direction: row;
overflow-x: auto;
scroll-snap-type: x mandatory;
gap: 16px;
```
Each pitch card:
```css
scroll-snap-align: start;
flex: 0 0 85vw;   /* ~85% viewport width so the next card peeks */
max-width: 400px;
```

On desktop (≥ 960px, two-column layout): pitch cards remain in `flex-col` (no
horizontal snap) — the column is wide enough for a list view.

**Keyboard / accessibility:** Horizontal scroll containers are keyboard
accessible via Tab (each pitch card is a focusable `<div>` with
`tabIndex={0}`) and arrow keys do not need special handling (native scroll).
Screen readers read cards in DOM order.

**Reduced-motion behavior:** Scroll-snap itself has no animation. The
`overflow-x: auto; scroll-snap-type: x mandatory` is CSS-only and does not
require a reduced-motion guard. Native scroll snapping is not classified as
"animation" under WCAG 2.3.3.

**Scrollbar:** `scrollbar-width: none` (Firefox) + `::-webkit-scrollbar { display: none }` for clean visual. Navigation is via swipe (touch) or Tab+arrow on keyboard.

## Accessibility Contract

Inherited from Phase 9. Phase 11 additions:

- **CardSwap:** A `<section aria-label="Archive preview">` wrapper. The card
  `<a>` elements have `aria-label="Issue {N}: {charityName}"`. Under
  reduced-motion, the static list (ArchiveList) is the primary accessible view;
  CardSwap may render a simplified no-animation version.
- **Indicator dots:** Each `<button>` has `aria-label="Issue {N}"` and
  `aria-current="true"` on the active dot. Focus order: prev button → dots →
  next button (or arrange by DOM order with `tabIndex`).
- **Prev/Next controls:** Real `<button>` elements with lucide-react chevron
  icons + `aria-label`. ≥44px hit area enforced.
- **Hero reveal:** Content is ALWAYS visible. The animation is cosmetic. No
  `aria-hidden` on the spans.
- **Confidence count-up:** The `<span>` that displays the animated number has
  `aria-live="polite"` so screen readers announce the final value after the
  count-up completes. The region is not announced during the animation
  (intermediate values are noisy); `aria-live` fires once on final value set.
- **Pitch card carousel:** The scroll container has `role="list"` and each card
  `role="listitem"`. A visually hidden note `<p className="sr-only">Scroll to
  see more candidates.</p>` is placed after the carousel on mobile.
- **Single `<main>`:** Phase 11 adds no new `<main>`. ArchivePage already has
  no `<main>` (the root layout owns it).
- **Print:** `.cardswap` wrapper tagged `data-print-hide="true"`. Already
  covered by the Phase 9 print rule. Hero word spans print as normal text
  (animation removed in print media — `@media print { * { animation: none; } }`
  is standard browser behavior).
