## Typography

### Type Scale

Four sizes. Two weights. The scale is fixed regardless of per-issue theme. Font *family* changes per issue via CSS variables; size and weight do not change.

| Role | Size | Weight | Line Height | Usage |
|------|------|--------|-------------|-------|
| Display | 36px (desktop) / 28px (mobile) | 600 (semibold) | 1.15 | Issue headline, charity name in hero, section headlines |
| Heading | 22px | 600 (semibold) | 1.25 | Sub-section labels, archive item charity names, page titles |
| Body | 18px | 400 (regular) | 1.65 | All editorial prose (Portable Text body fields) |
| UI | 14px | 400 (regular) | 1.5 | Nav links, labels, captions, reading time, metadata, error copy |

**Weights used: 400 (regular) and 600 (semibold) only.** No 300, 500, 700, 800. The restraint is intentional — Jesse's brand is dry and precise; no typographic warmth from weight variation.

### CSS Variable Typography System

The per-issue theme overrides font families via two CSS variables set on `<html>`:

```css
--font-display: 'Playfair Display', serif;   /* default fallback */
--font-body: 'Lora', serif;                   /* default fallback */
--font-ui: 'Inter', sans-serif;               /* NEVER overridden by theme */
```

Tailwind v4 `@theme` directive wires these:

```css
@theme {
  --font-display: var(--font-display);
  --font-body: var(--font-body);
  --font-ui: var(--font-ui);
}
```

Usage in Tailwind classes: `font-display`, `font-body`, `font-ui`.

**`--font-ui` is never overridden by the DesignAgent.** Navigation, reading time, metadata, error copy, and UI chrome always render in the UI font. Only `--font-display` (section headlines, charity name) and `--font-body` (prose body) change per issue.

### Default Google Font Set (Phase 2)

Six fonts loaded by default; font whitelist is locked in Phase 5. These six cover the editorial range without waiting for Phase 5.

| Variable | Default | Classification | Why |
|----------|---------|---------------|-----|
| `--font-display` | Playfair Display | Serif display | Editorial authority; high contrast; WeasyPrint-safe |
| `--font-body` | Lora | Serif body | Long-form readability; WeasyPrint-safe |
| `--font-ui` | Inter | Sans-serif | Neutral; never themed; system-default fallback available |
| (alt display) | Cormorant Garamond | Serif display | Lighter, elegant; DesignAgent may select |
| (alt body) | Merriweather | Serif body | Heavier, robust for technical content |
| (alt display 2) | DM Serif Display | Serif display | Modern editorial; WeasyPrint-safe |

**Font loading:** All six loaded via `next/font/google` in `apps/web/app/layout.tsx` as CSS variables. Phase 6 WeasyPrint templates use base64-bundled `@font-face` declarations of the same six fonts (no HTTP load at PDF render time).

**Font injection in `apps/web/lib/theme.ts`:**

```typescript
// Pseudo-code — executor implements
const FONT_WHITELIST = ['Playfair Display', 'Lora', 'Inter', 'Cormorant Garamond', 'Merriweather', 'DM Serif Display']

export function applyTheme(el: HTMLElement, theme: IssueTheme): void {
  // Validate and apply colors
  const hexRe = /^#[0-9a-fA-F]{6}$/
  const applyColor = (varName: string, value?: string, fallback: string) => {
    const safe = value && hexRe.test(value) ? value : fallback
    el.style.setProperty(varName, safe)
  }
  applyColor('--color-primary',    theme.primaryColor,    BRAND_DEFAULTS.primary)
  applyColor('--color-accent',     theme.accentColor,     BRAND_DEFAULTS.accent)
  applyColor('--color-bg',         theme.backgroundColor, BRAND_DEFAULTS.bg)
  applyColor('--color-text',       theme.textColor,       BRAND_DEFAULTS.text)

  // Validate contrast; apply fallback palette if WCAG AA fails
  if (!passesWcagAA(theme.textColor, theme.backgroundColor)) {
    applyColor('--color-bg',   undefined, BRAND_DEFAULTS.bg)
    applyColor('--color-text', undefined, BRAND_DEFAULTS.text)
  }

  // Validate and apply fonts
  const applyFont = (varName: string, value?: string, fallback: string) => {
    const safe = value && FONT_WHITELIST.includes(value) ? `'${value}', serif` : fallback
    el.style.setProperty(varName, safe)
  }
  applyFont('--font-display', theme.fontDisplay, "'Playfair Display', serif")
  applyFont('--font-body',    theme.fontBody,    "'Lora', serif")
  // --font-ui is never set from theme data
}
```

**Claude's discretion — contrast check method:** Use the WCAG luminance formula directly in `applyTheme` (no third-party lib needed; ~15 lines of math). A passing ratio is ≥ 4.5:1 for body text (WCAG AA). If contrast fails, apply the brand default palette without crashing and log a warning to the console. Per WEB-09.

## Color System

### CSS Variable Scheme

All colors live on `<html>` as CSS variables, set by `applyTheme()` on issue pages.

| Variable | Purpose | 60/30/10 |
|----------|---------|---------|
| `--color-bg` | Page background | 60% — dominant surface |
| `--color-surface` | Cards, nav, deliberation panel background | 30% — secondary (derived: `--color-bg` darkened or lightened 8%) |
| `--color-text` | All body text | 60% usage on bg surface |
| `--color-text-muted` | Metadata, captions, reading time | Derived: `--color-text` at 60% opacity |
| `--color-primary` | Section headlines, anchor text | 10% — accent |
| `--color-accent` | CTAs (shop callout button), anchor copy confirmation | 10% — accent |
| `--color-border` | Dividers, section separators | Derived: `--color-text` at 12% opacity |

**`--color-surface` derivation:** Because the DesignAgent only emits four color fields, `--color-surface` is derived in CSS: slightly offset from `--color-bg` using `color-mix()` in Tailwind v4. The executor should implement this as a CSS custom property computed from `--color-bg`:

```css
--color-surface: color-mix(in srgb, var(--color-bg) 92%, black 8%);
```

On dark-background issues, invert the mix direction to lighten instead. Detect via WCAG luminance: if `--color-bg` luminance < 0.5, mix with white 8%.

**Claude's discretion on surface derivation:** This keeps the DesignAgent's output minimal (4 hex values) while giving the UI 7 usable color roles. The alternative (DesignAgent emitting 7 colors) introduces more validation surface area and more LLM output complexity. Defer DesignAgent expansion to Phase 5 if needed.

### Brand Default Palette (Fallback)

Applied when a theme is absent, invalid, or fails WCAG AA contrast check.

| Variable | Value | Notes |
|----------|-------|-------|
| `--color-bg` | `#FAFAF8` | Off-white; warm, editorial, not clinical |
| `--color-surface` | `#F0EFE9` | Warm cream; slight warmth above bg |
| `--color-text` | `#1A1A18` | Near-black; high contrast on default bg |
| `--color-text-muted` | `#1A1A18` at 60% | CSS: `color-mix(in srgb, #1A1A18 60%, transparent)` |
| `--color-primary` | `#2D5016` | Forest green; editorial authority |
| `--color-accent` | `#8B1A1A` | Deep crimson; restraint as CTA color |
| `--color-border` | `#1A1A18` at 12% | Subtle divider |

**Rationale:** The default palette reads like a well-edited print magazine — muted, warm, high-contrast. It does NOT look like a SaaS product or a charity website. If DesignAgent fails entirely, the fallback should still feel intentional.

### Accent Reserved For

`--color-accent` is used on exactly these elements:

1. Shop callout button (single CTA per issue page)
2. "Copied" confirmation state on anchor copy-link buttons
3. Advocate score bar fill in the deliberation layer (Phase 9 — reserve the variable now)
4. External links within editorial prose (underline color only; the link text stays `--color-text`)

**Not used for:** Headlines, section dividers, navigation, hover states on non-CTA elements, any decorative element. The accent is the interrupt color — it must appear rarely enough to command attention when it does.

### Semantic Color: Destructive

No destructive actions exist in Phase 2. Anchor copy-link has no destructive confirmation. Archive search has no destructive actions. Reserve `--color-destructive: #B91C1C` for future phases. Do not render it in Phase 2.

### Non-Issue Pages (Archive, Charities, About, Shop Shell)

Non-issue pages do not receive a per-issue theme. They render in the brand default palette (above), honoring `prefers-color-scheme` via a Tailwind `dark:` variant that darkens the default palette:

- `dark: --color-bg: #1A1A18`
- `dark: --color-text: #FAFAF8`
- `dark: --color-surface: #252520`

Dark mode is a CSS-only toggle via `@media (prefers-color-scheme: dark)`. No JavaScript required. No manual toggle button.

## Reading Time (WEB-15)

**Calculation:** Server-side (in the RSC for `/issue/[slug]`), not client-side.

**Formula:** Count all text nodes in `originStory.body`, `problemStatement.body`, `founderBio.body`, `caseStudy.body`, `bonus.body` Portable Text arrays. Sum word count. Divide by 238 (average adult reading speed). Round up to nearest integer.

**Excluded from count:** game description, podcast description, section headlines, charity metadata.

**Display:** `{N} min read` — placed in `<IssueHero>`, right-aligned on the metadata row, UI font 14px muted.

**Helper function location:** `apps/web/lib/reading-time.ts` — accepts an array of Portable Text blocks, returns a number (minutes).

## Security Contract (Theme Engine)

All security rules are implementation requirements, not guidelines.

### Hex Color Validation (WEB-07)

Before any CSS variable is set, validate with `/^#[0-9a-fA-F]{6}$/`. Reject and fall back to brand default if:
- Value is undefined or null
- Value is not a string
- Value does not match the regex
- Value is a named color (e.g., "red", "blue") — REJECTED even if valid CSS

### setProperty API (WEB-08)

Use `element.style.setProperty('--variable-name', value)` ONLY. Forbidden patterns:
- `element.style.cssText = ...`
- Template literals in `<style>` tags constructed from theme data
- Inline `style={{ '--color': themeValue }}` where `themeValue` is unvalidated

### Font Name Validation

Before loading a Google Font via `next/font/google` or injecting `--font-display`/`--font-body`:
- Check font name against `FONT_WHITELIST` array in `apps/web/lib/theme.ts`
- Reject and fall back to default if not in whitelist
- The whitelist is hardcoded in Phase 2 (6 fonts listed in Typography section)
- Phase 5 expands the whitelist after Andrew/designer approval

### WCAG AA Contrast (WEB-09)

Implement `passesWcagAA(textColor: string, bgColor: string): boolean` in `apps/web/lib/theme.ts`:
- Compute relative luminance per WCAG 2.1 formula
- Pass if contrast ratio ≥ 4.5:1 (body text AA)
- On fail: apply brand default `--color-bg` and `--color-text` (not the theme values); log `console.warn` with the failing pair and ratio
- Do NOT throw an error; do NOT crash the page

### No AI Attribution

No component, page, or metadata may contain:
- Model names ("Claude", "GPT", "Sonnet", "OpenRouter")
- "Powered by AI" copy or badge
- "AI-generated" label in visible UI
- Attribution of content to a specific LLM

The deliberation layer (Phase 9) attributes content to *named agent characters* (Scout, Advocate, Editor) from `agentProfile` documents. That is the full transparency mechanism.
