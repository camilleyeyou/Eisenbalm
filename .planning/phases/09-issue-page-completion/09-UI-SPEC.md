### Invariants (carry forward from theme.ts — DO NOT break)

1. `--font-ui` is NEVER themed (locked to `'IBM Plex Mono', monospace` pending whitelist approval; fallback Inter — see Fonts). theme.ts already excludes it from injection.
2. Only validated values reach a CSS variable: hex via `validateHex`, fonts via `FONT_WHITELIST`. No new injection path.
3. `element.style.setProperty(...)` ONLY for runtime injection. No `cssText`, no `innerHTML` from theme data, no template-literal `<style>` from theme values.
4. WCAG AA gate (≥4.5:1) gates the `--color-bg` + `--color-text` pair; failing pairs fall back to `BRAND_DEFAULTS`. Per-issue accent/primary keep validated values.
5. House identity colors (`--color-scout`, `--color-advocate`, derived lines/glows) are NOT theme-overridable and must remain AA on the dark house bg (verified below).

### Theme-override behavior (the "hybrid" guarantee)

- A per-issue theme that supplies a light `backgroundColor`/`textColor` is honored (theme.ts already does this) — the page is NOT forced dark. The dark palette is the DEFAULT, not a hard lock.
- The accent layer (`--color-primary`, `--color-accent`) visibly changes per issue: `§` marks, link underlines, confidence-bar fill, selected-pitch border, hover glows. Switching issues with different theme hexes must visibly change these without breaking layout or hierarchy (mirrors DES-06).
- Derived house tones (`--color-surface`, `--color-card`, lines, glows) are `color-mix()` of `--color-bg` / `--color-text` so they track whatever bg/text the theme resolves to.

### WCAG AA gate for secondary tones (LOCKED hard constraint)

The theme engine only gates the bg+text pair. Secondary tones are NOT gated, so this spec specifies AA-passing values (verified by the contrast math in `theme.ts`):

| Tone | Mockup value | Ratio on bg/panel/card | Decision |
|------|-------------|------------------------|----------|
| `--color-text-dim` | `#A89F8A` | 7.5 / 7.2 / 6.9 | **KEEP** — AA at all sizes |
| `--color-text-mute` | `#615B4D` (mockup) | 2.9 / 2.8 / 2.7 | **REJECT — FAILS AA.** Replace with **`#938A77`** (5.8 / 5.5 / 5.3 — AA at all sizes) |
| `--color-accent` ember | `#C2502A` | 4.2 / 4.0 / 3.8 | **AA-large ONLY** (≥18px regular or ≥14px bold). MUST NOT be used for body-size text. Borders/large headings/icon fills only. The warning note ("below 0.70 threshold") MUST be ≥18px OR use `--color-text-dim` for the text and ember only for an icon/border. |
| `--color-scout` / `--color-advocate` / `--color-primary` / `--color-primary-bright` | as above | all ≥6:1 | KEEP — AA |

Build-time/test guidance: the executor should reuse `theme.ts` `contrastRatio()` in a unit assertion that each house secondary tone ≥ 4.5:1 (or ≥3:1 with a documented large-text-only constraint for ember) against `--color-bg` `#0C0B0A`.

## Deliberation Contract (DEL-01..06) — functional heart

### Data binding (LIVE Convex — never hardcoded)

The mockup's hardcoded FBC/CSJ/Steve-Morgan content is a fixture only. Components bind to live Convex via `useQuery`, keyed on `issue.runId` (from `QUERY_ISSUE_RUN_ID` / already on the `Issue` type as `runId: string | null`).

| UI element | Source (Convex query) | Notes |
|------------|----------------------|-------|
| Pitch log cards (left column) | `api.pitchLog.byRunId` | `charityName`, `charityLocation`, `scoutSummary`, `selected` (→ `.selected` styling + "★ Selected this week" / "Runner-up" badge) |
| Timeline events (right column) | `api.deliberationEvents.byRunId` | ordered asc; render Scout/Advocate/Editor events; `payload` JSON parsed per `eventType` |
| Advocate score bars (DEL-02) | `api.agentVotes.byRunId` (+ advocate-argument events) | Render a 0–10 horizontal bar per candidate. **If score is null** (real Issue 999 case), render "Scores did not complete this cycle" — NO fabricated bar. |
| QA severity color-coding (DEL-02) | `api.qaCorrections.byRunId` | severity → color map above; each row shows section, reason, severity LABEL+color |
| Editor confidence meter | `api.pipelineRuns.byRunId` + editor-decision event payload | Fill width = confidence; value count-up (reduced-motion: jump to final, no animation). **Below 0.70 → ember "human review flagged" note.** |
| Agent identity cards (DEL-02, DEL-06) | Sanity `QUERY_AGENT_PROFILES` (§1.6) joined by `agentId` | Show `displayName`, `role`, optional avatar; the whole card LINKS to the agentProfile page. NEVER the model name. |

### Loading / empty / error states

| State | Trigger | UI |
|-------|---------|----|
| Loading | any `useQuery` returns `undefined` | Skeleton or quiet "Loading the deliberation." (period). No layout jump. |
| Empty (DEL-05) | `issue.runId == null` OR all queries return `[]`/`null` | Graceful empty state inside the collapsed section: "This issue predates the open deliberation record." (period). NO error, NO broken UI. |
| Run-in-progress (DEL real-time, success criterion 4) | `pipelineRuns.status == 'running'` | Live updates as events arrive (Convex subscription latency); a small "live" dot on the column label. No refresh required. |
| Error | query throws | Fail soft to the empty state; console.error only. Never crash the page. |

### Collapse behavior (DEL-03)

Collapsed by default. Keep the existing `<details>/<summary>` progressive-enhancement pattern (zero-JS, keyboard-operable, WCAG-friendly). Summary copy: "How this issue was made" (existing). Chevron rotates on open (reduced-motion neutralizes the rotate transition — already covered by the guard). The two-column grid renders inside the expanded body.

### No-model-names rule (DEL-04 — LOCKED)

NO underlying model name ("Claude", "GPT", "Sonnet", "Haiku", "OpenRouter", "written by AI", etc.) anywhere in the deliberation UI, agent cards, payloads surfaced to the reader, tooltips, or alt text. Agents are the named personas only (Scout / Advocate / Editor / etc. from `agentProfile.displayName`). The executor must NOT render `pipelineRuns.cost.modelVersions` or any model string to the reader.

## Motion Contract (LOCKED — prefers-reduced-motion)

EVERY animation/transition the mockup introduces MUST be neutralized under `@media (prefers-reduced-motion: reduce)`. The existing guard in `globals.css` already forces `animation-duration`/`transition-duration` to ~0 and `scroll-behavior:auto`. For JS-driven motion, add explicit `matchMedia('(prefers-reduced-motion: reduce)').matches` early-returns:

| Motion | Type | Reduced-motion behavior |
|--------|------|------------------------|
| Aurora shift | CSS animation | static (guard) |
| Grain shift | CSS animation | static (guard) |
| Scroll progress bar | JS (scroll → width) | JS early-return → bar hidden or static 0; no per-scroll update |
| Hero line reveal / fadeUp | CSS animation | content visible immediately (guard makes duration ~0) |
| Section-card magnetic glow | JS (mousemove → --mx/--my) | JS early-return; static centered glow on hover only |
| Section reveal-on-scroll (IntersectionObserver `.in`) | JS + CSS transition | JS must add `.in` immediately (or skip observer) so content is never stuck at `opacity:0`; transition ~0 via guard |
| Play-button ripple | CSS animation | static (guard) |
| Confidence count-up | JS interval | JS early-return → set final value directly, set fill width with no transition |
| Transcript max-height expand | CSS transition | instant (guard) |
| Nav scroll blur/border | CSS transition | instant (guard); state still applies |

CRITICAL: any `opacity:0`-by-default reveal element MUST become visible under reduced-motion (never trapped invisible). The IntersectionObserver fallback / immediate `.in` add is mandatory.
