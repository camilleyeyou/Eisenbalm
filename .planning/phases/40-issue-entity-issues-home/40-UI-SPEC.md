## Spacing Scale

Declared values (8-point scale, confirmed for this phase's layout-level spacing):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon-to-label gap inside a chip/readout |
| sm | 8px | Compact stack spacing (card internal rows, stage-strip segment gaps) |
| md | 16px | Default card padding, grid gap between minor cards (held-issue rows, published rows) |
| lg | 24px | Issues-home page gutter, gap between primary card and secondary cards (scheduled slot, held list) |
| xl | 32px | Page-level top/bottom padding on `/issues` |
| 2xl | 48px | Section break between "in progress" / "scheduled" / "held" / "recently published" groups |
| 3xl | 64px | not used this phase |

**Exceptions (confirmed, continuing an established project pattern — do not "fix" these to the 8pt scale):**
- Chip/pill/badge internal padding uses pixel-exact arbitrary values (`px-[9px] py-[3px]`, `px-[12px] py-[5px]`, gaps of `2px`/`6px`/`10px`) — this is the existing convention in `Masthead.tsx` and `AppSidebar.tsx` group labels, kept for the new header readouts and stage-strip segments so they visually match the shipped chrome exactly.
- **All interactive targets (nav links, card click areas, dialog buttons, stage-strip segments) are ≥44px** regardless of visual padding — established and tested convention (`AppSidebar.tsx`, `AwaitingYouInbox.tsx`, `AddCharityDialog.tsx` all use `min-h-[44px]`). This is a hard floor, not a spacing token.

## Typography

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 13px, `font-ui` (Space Grotesk) | 400 (regular) | 1.5 (`leading-relaxed`) |
| Label | 10.5–11px, `font-ui`, uppercase, `tracking-[.06em]`–`tracking-[.09em]` | 600 (semibold) | 1.2 |
| Heading | 16px, `font-display` (Newsreader) | 600 (semibold) | 1.25 |
| Display | 22–24px, `font-display` | 600 (semibold) | 1.15 |

Exactly 2 weights declared: **400 regular** (body/data copy, e.g. hold reason text, task descriptions, cost figures) and **600 semibold** (all labels, headings, and the one Display use — the `/issues` page `<h1>`). No other weights are introduced.

Numeric/data values (cost figures, issue numbers, counts) render at **Label size in `font-mono`** rather than a fifth type size — matches `Masthead.tsx`'s existing `$${cap}` / `Issue {n}` treatment.

## State & Icon Contract (ISS-05 / ISS-06 — label + icon, never color alone)

Four state systems, **never blended visually or spatially** (per D-24 / `DERIVED-STATE-CONTRACT.md` §3). Every state below renders its **label text and its icon together** — color is a reinforcement, never the sole signal. `lucide-react` icon names are exact import names.

### 1. Issue status (header + issue card)
| State | Icon | Color | Label |
|---|---|---|---|
| Draft | `FileEdit` | `--color-ink-soft` | "Draft" |
| Needs review | `AlertTriangle` | `--color-marigold-text` | "Needs review" |
| Ready to publish | `CheckCircle2` | `--color-green` | "Ready to publish" |
| Published | `BadgeCheck` | `--color-green` | "Published" |
| Held | `PauseCircle` | `--color-vermilion` | "Held" |

### 2. System activity (header only — must read as visibly distinct from Issue status, never share a container)
| State | Icon | Color | Label |
|---|---|---|---|
| Idle | `Circle` | `--color-faint` | "Idle" |
| Running | `Loader2` (spin animation) | `--color-cobalt` | "Running" |
| Paused for you | `PauseCircle` | `--color-marigold-text` | "Paused for you" |
| Failed | `AlertTriangle` | `--color-vermilion` | "Failed" |
| Complete | `CheckCircle2` | `--color-green` | "Complete" |

**Rule:** `Loader2` (spin) is reserved exclusively for System Activity "Running." The stage strip's "In progress" (below) uses a static, non-spinning icon — conflating the two would blend two state systems the design explicitly separates.

### 3. My Tasks readout (header)
| State | Icon | Color | Label |
|---|---|---|---|
| Count = 0 | `ListChecks` | `--color-ink-soft` | "My Tasks · 0" (still rendered — no capability lost, no dead button per D-25) |
| Count > 0 | `ListChecks` | `--color-vermilion` | "My Tasks · {n}" |

### 4. Cost vs budget (header)
| State | Icon | Color | Label |
|---|---|---|---|
| Under cap | `CircleDollarSign` | `--color-ink-soft` | "${mtd} / ${cap}" (`font-mono`) |
| At/over cap | `CircleDollarSign` | `--color-vermilion` | "${mtd} / ${cap}" (`font-mono`) |

### 5. Stage-strip segments (issue card, 5 segments)
| State | Icon | Color | Label |
|---|---|---|---|
| Not generated | `Circle` (outline) | `--color-faint` | "Not generated" (first-class, never a blank dash) |
| In progress | `CircleDot` (static, no animation) | `--color-marigold` | "In progress" |
| Needs you | `AlertTriangle` + count | `--color-vermilion` | "Needs you · {n}" |
| Clean | `CheckCircle2` | `--color-green` | "Clean" |

### 6. Error state (ISS-06 — card-level, replaces the whole card body)
| State | Icon | Color | Label |
|---|---|---|---|
| Status failed to load | `AlertTriangle` | `--color-vermilion` | "State unknown — refresh" (button/link, re-triggers the query — **never renders a stale "Ready" or "Clean" value**) |

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA | **"Find a story with agents"** — the one Create path this phase ships (D-28). Second path ("Start from my brief") is Phase 48 scope; layout must reserve space for a second card so its later addition is not a redesign. **No dead button.** |
| Secondary actions | "Open issue" (in-progress card click) · "Start #{n} early" (scheduled slot) · "Reopen" (held issue) · "Hold issue" (persistent control on `/issues/[n]`) |
| Empty state heading | "No issue in progress" |
| Empty state body | "No issue in progress — discovery scheduled {day} {time}." (e.g. "…scheduled Monday 6:00.") The Create panel renders **open by default** in this state — it is not a separate click. |
| Loading state | No copy — card skeletons that **preserve the 5-stage-strip geometry** (same width/segment layout as the loaded card), so the layout does not jump on load. |
| Error state | **"State unknown — refresh"** (ISS-06) — renders in place of the card body, never a silently stale prior value. Clicking re-runs the query. |
| Hold dialog heading | "Hold this issue" |
| Hold dialog field label | "Reason" — required, free text, placeholder "Why are you holding Issue {n}?" |
| Hold dialog checkbox | "Also stop the run in progress" — **default checked** (D-14) |
| Hold dialog confirm | "Hold issue" |
| Hold dialog cancel | "Cancel" |
| Hold validation error | "A reason is required to hold this issue." |
| Reopen | Single-click action, **no confirmation dialog** — reopening is additive/safe, status re-derives on its own (D-17). |
| Held-issue row format | "Held · {reason} · {heldBy} · {relative time}" + "Reopen" action |
| Repetition note (scheduled slot) | Exact shape: **"avoid {X} · avoid {Y}"** (e.g. "avoid US-SE · avoid weather") — derived deterministically from coverage memory, never a Calibrator run-output. Precise wording beyond the "avoid X · avoid Y" shape is Claude's discretion per CONTEXT.md. |
| Recently-published verification labels | "Facts cleared by {actor} · {time}" · "Voice approved by {actor} · {time}" · "{checked} of {total} claims checked" — data-driven from `sign_offs` / `claim_checks`; **an empty verification slot is never rendered** — absence would read as "unverified," which the spec explicitly bans ("blank never means verified," D-29). |
| Header rename | **"Human approval required"** replaces "Auto-publish OFF" — quiet reassurance, not a switch (D-26). When auto-publish is ON, the existing loud vermilion `AutoPublishBanner` warning is unchanged. |
| Destructive confirmation | **Not applicable this phase** — no irreversible action ships. Hold requires a reason (friction, not confirmation-typing); Mark Do-not-use (the milestone's one typed-confirmation destructive action) is Phase 39/Editorial Memory scope, not Phase 40. |

## Component Inventory

**New components this phase builds:**
- `IssuesHomePage` (`/issues`) — page shell: in-progress card, scheduled-slot card, held-issues list, recently-published list, Create panel.
- `IssueCard` — the in-progress card: 5-stage strip, issue status, open-task count, claim coverage, voice state, estimated work remaining, run cost. Skeleton variant preserves stage-strip geometry.
- `StageStrip` — 5-segment status strip (shared shape consumed later by Phase 41's stage tabs — build the visual contract once here).
- `ScheduledSlotCard` — next slot, repetition note, "Start #{n} early".
- `HeldIssueRow` / `RecentlyPublishedRow` — list rows for held and published issues.
- `CreatePanel` — one enabled Create path + one visually-reserved (not rendered as a dead button — simply absent) slot for Phase 48's second path.
- `HoldDialog` — inline panel (not shadcn `Dialog`), reason field + "also stop the run" checkbox.
- `IssueOverviewPage` (`/issues/[n]`) — stage strip, status, open tasks, Hold control, links into re-keyed `/issues/[n]/review` and `/issues/[n]/voice`, run history link. Phase 41 replaces its **contents** in place at this same URL.
- Global header readouts (4): rebuild of `Masthead.tsx` per the State & Icon Contract above — replaces the single blended "pipeline-state chip."

**Modified:**
- `apps/dispatch-control/lib/nav.ts` — `NAV_GROUPS` restructure: **Editorial** (Issues only this phase — My Tasks/Workspace join later) · **System Workbench** (Run Details/Monitor, Prompt Lab, Eval Center, Registry) · **Operations** (Config, Finance, Settings). Review Desk / Signal Desk / Voice Pass leave the nav (become issue sub-routes). `AppSidebar.tsx` itself needs no visual changes — it already renders whatever `NAV_GROUPS` contains; the 44px targets, active-border formula, and group-label styling (`text-[9px] uppercase tracking-[.14em]`) carry over unchanged.
- `AwaitingYouInbox.tsx` — becomes the My Tasks dropdown target (D-25); trigger button relabeled from "Awaiting you" to the `My Tasks · {n}` readout treatment above. Dropdown internals unchanged this phase.

**Reused, unchanged:**
- `sign_offs` / `claimChecks` Convex queries — source of `factDone`/`voiceDone`/claim coverage (no new gate logic).
- 1c color/font tokens in `app/globals.css`.
- `lucide-react` (already a dependency).
- 44px touch-target convention, focus-visible ring convention (`focus-visible:ring-2 focus-visible:ring-[color:var(--color-vermilion)]` per `AppSidebar.tsx`).
