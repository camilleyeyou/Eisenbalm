**Legacy data (LOCKED)**

## Summary

The 234-click problem is produced by two independent defects that both live at the END of the pipeline and in `convex/claimChecks.ts`: (1) the publisher seeds one `claim_checks` row per regex match (`lib/claims.py` `RE_NUMBER`/`RE_DATE`/`RE_PROPER_NOUN`, run per block by `extract_claims_by_block`) so bare tokens like "2015" and "Tameka Diaz" become rows, in addition to the few writer-declared `claimSpans`; (2) the schema has no verdict, so `allSignedOff` can only mean "a human touched every row" (`convex/claimChecks.ts:298-316`, `signedOff = status !== 'pending'`, `allSignedOff = total > 0 && signedOff === total`).

Everything needed is already in reach. The publisher is the single call site of `claimChecks:insertBatch` (`agents/publisher/__init__.py:225`), already builds the full merged row list, and the Researcher already holds the retrieved Tavily passages - but it throws them away: `tavily_results` is a local in `researcher()` (`agents/researcher.py:219-237`) and only `{claimId,text,sourceUrl,retrievedAt,importance}` survive into `state['research']['claims']`. So the single hard prerequisite for a batched verdict call is **persisting the retrieved passages into state** (new key, NOT inside `state['research']`, because every writer prompt embeds `research` verbatim - `agents/origin_story.py:109,130`).

Gate semantics are the drift hazard. `allSignedOff` has exactly 3 dashboard consumers + 1 server consumer, but the same "pending == needs a human" meaning is independently re-implemented in ~10 other client places (`derivedState.ts:214,497-499`, `RunScreen.tsx:655-657,281`, `ApprovalPanelContent.tsx:62`, `FactCheckPanelContent.tsx:48`, `DecisionRail.tsx:222-224`, `SourceIndex.tsx`, `FactCheckScreen`, `issues/page.tsx:309`, `AwaitingYouInbox.tsx:66`, `isMustFix` `derivedState.ts:393`). **Recommendation: keep the name `claimChecks:allSignedOff` and change its meaning to "no open contradicted claim"; define the open/flagged predicates ONCE in a pure module (`convex/lib/claimGate.ts`) imported by both the Convex queries and the dashboard via the existing `@convex/*` alias.** Then `signoffs.py` needs no logic change and cannot drift.

**Primary recommendation:** No new LangGraph node. Add `lib/claim_verdicts.py` (one Haiku-4.5 batched structured call, index-bound sources) invoked from the publisher BEFORE `end_run()`; persist Tavily passages to a new `state['research_sources']`; make extraction sentence-level; add additive optional `verdict*` fields; re-semanticize `allSignedOff` through one shared predicate; filter the galley/derived tasks to flagged claims; demote (don't delete) the ledger screens.

### Pattern 1: Index-bound sources (reuse §35.1 discipline)
The verdict LLM receives numbered passages `[S0]..[Sn]` and numbered claims `[C0]..[Cm]`; it returns claim indices + source indices only. Code maps source index -> real URL. A hallucinated URL is structurally impossible (identical to `researcher._map_claims`, `researcher.py:112-141`).

```python
# lib/claim_verdicts.py (sketch)
class ClaimVerdict(BaseModel):
    claimIndex: int
    verdict: Literal["verified", "contradicted", "unverifiable"]
    evidence: str = ""              # <= ~300 chars
    sourceIndexes: list[int] = Field(default_factory=list)

class VerdictBatch(BaseModel):
    verdicts: list[ClaimVerdict] = Field(default_factory=list)

out, usage = await acomplete(agent_id="fact_check", run_id=run_id,
                             messages=msgs, response_format=VerdictBatch)
```
Code-side guards (mandatory): (a) `contradicted` with no valid `sourceIndexes` is downgraded to `unverifiable` - a hallucinated contradiction is the only way this phase can wrongly BLOCK publish; (b) claimIndex not in the batch is ignored; (c) claims the model omitted get NO verdict (neutral, non-blocking); (d) clip `evidence` to 400 chars; (e) stub mode (`model_construct()` -> empty list) yields all-unverdicted.

### Pattern 2: Single shared predicate (anti-drift)
```ts
// convex/lib/claimGate.ts  (pure, no ctx) - imported by claimChecks.ts AND by dispatch-control via '@convex/lib/claimGate'
export const isOpenBlocking = (r) =>
  r.verdict === 'contradicted' && r.status === 'pending' && r.changedSinceCheck !== true
export const isEditorFlagged = (r) =>
  r.status === 'pending' && r.changedSinceCheck !== true &&
  (r.verdict === 'contradicted' ||
   (r.verdict === 'unverifiable' && (r.importance ?? 'Supporting') === 'Load-bearing'))
```
Legacy row (`verdict` undefined) => both false. `status` `checked|skipped|removed` (editor action) => resolved; the verdict itself is never overwritten (locked: editor action recorded separately).

### Anti-Patterns to Avoid
- **Renaming/removing `allSignedOff`:** its 4 readers would silently read `undefined`/falsy and fail closed or open unpredictably. Keep the name, change the meaning, document it.
- **Re-implementing the gate in Python:** `signoffs.py` must keep asking Convex (`signoffs.py:115-117`). Do not mirror the predicate in Python.
- **Putting source passages in `state['research']`:** bloats every section-writer prompt (`origin_story.py:130` passes `research=research`).
- **Per-claim LLM calls / new Tavily searches:** locked out.

## Detailed Findings (answers to the 10 research questions)

### Q1. Claim extraction

- **Where:** only the publisher node (last node, `agents/publisher/__init__.py:99-241`), wrapped in best-effort try/except. Two sources merged: (1) SOURCED rows from each prose writer's `claimSpans` (`publisher/__init__.py:138-181`), bound to `state['research']['claims']` by `claimId`; (2) UNSOURCED rows from `lib/claims.py::extract_claims_by_block` (`claims.py:...` regexes `RE_NUMBER`, `RE_DATE`, `RE_PROPER_NOUN` at the top of the file), minus any whose normalised text equals a sourced span in the same `(section, block)` bucket (`publisher/__init__.py:184-194`). This is run-end, not the Researcher and not QA. `lib/claims.py` is documented "No LLM calls - full recall is the acceptance bar".
- **Root cause of "Rare Disease Day" / "2015" / "Tameka Diaz":** `_extract_from_text` emits `m.group(0)` of each regex match as `text`; `RE_DATE` matches any `19xx/20xx` and `RE_PROPER_NOUN` matches any 2-5 word Title-Case run. The 2-5 word cap and heading/blockquote skips (`_MAX_PROPER_NOUN_WORDS`, `_HEADING_BLOCKQUOTE`) were band-aids on this unit-of-extraction error.
- **Field population today:** `claimType` = `"sourced"` for writer spans (`publisher:158`) or `number|date|proper_noun` for regex rows; `claimId` only on writer rows (format `{run_id[:8]}-{i}` from `researcher._map_claims`, `researcher.py:134`); `sourceUrl`/`retrievedAt` only when the span's `claimId` resolves AND the Researcher's `sourceIndex` was a valid index (`researcher.py:127-131`); `importance` from Researcher tier via the claimId lookup, else `Supporting` (`publisher:177`, unsourced hard-coded `Supporting` at `:193`); `claimIndex` assigned globally after merge (`:218-220`).
- **Why ~58% lack `sourceUrl` (code-derived, not measured):** by construction EVERY regex row is unsourced (no `claimId`, no URL), and writer rows are unsourced when the Researcher emitted `sourceIndex=None`/out-of-range or the writer's `claimId` does not resolve. The exact split cannot be measured offline (no Convex read access here); the plan should add a one-time count query/log in verification. The implication is the same either way: the verdict judge must run against the research corpus as a whole, not only the claim's own source.
- **Minimal change:** add `extract_assertions_by_block(sections)` in `lib/claims.py` (keep `extract_claims_by_block`/`extract_claims` untouched for back-compat, as the file already does): split each non-heading prose block into sentences; a sentence becomes ONE row iff it contains >=1 `RE_NUMBER`/`RE_DATE`/`RE_PROPER_NOUN` match; `text` = the sentence (exact substring of the block so `resolveSectionFindings` resolves it), `claimType` = type of first match, `context` = sentence (+/- neighbour trimmed), dedupe by normalised sentence within block. Drop a sentence row when a writer `claimSpans.asWritten` lies inside it (same block) - the sourced row already covers it (replaces the equality test at `publisher:187`). Also drop rows whose ONLY match is the charity/founder/subject name already known from `state` (a name alone is not an assertion). Publisher switches from `extract_claims_by_block` to the new function. Expected effect: ~234 token rows -> tens of sentence rows.
- Risk: sentence-level washes are longer; `findingClaimLink.claimForFinding` (greatest-overlap, ties lower `claimIndex`, `findingClaimLink.ts:40-58`) still picks a deterministic claim. Existing tests pin token-level behaviour: `tests/test_claims_extractor.py`, `tests/test_publisher_importance.py`, `tests/agents/publisher/test_publisher.py:480+`. The old functions stay, so those tests stay green; new tests target the new function.

### Q2. Sources available for a verdict

- Tavily results (`SearchResult{url,title,content,score}`, `lib/search_client.py:25-30`; <=4 results x 5 queries = <=20 passages; prompt truncates to `content[:1200]`, `researcher.py:~190`) live ONLY in a local variable inside `researcher()`. Persisted: `state['research']['claims']` (text/sourceUrl/retrievedAt/importance), founder/subject fields + `summary`/`founderBio`/`subjectStory`/`fundingSources` (`ResearchOutputModel`, `researcher.py:60-80`). `ResearchOutput.sources: list[str]` exists in `state.py:100` but the Researcher model never fills it. `verify_research` fetches founder/subject URLs but stores only booleans.
- Tavily `content` is a short snippet, not the full page; judging against it will yield many `unverifiable` - acceptable (never blocks), and Load-bearing ones surface to the editor in the sentence.
- **Required change:** in `researcher()` add `"research_sources": [{"index": i, "url": r.url, "title": r.title, "content": r.content[:1500], "retrievedAt": ...} for ...]` to the returned state, and add `research_sources: NotRequired[list[dict]]` to `DispatchState` (`graph/state.py`; LangGraph rejects undeclared keys; also mirror in `docs/API_CONTRACTS.md` §7 and `types.py` if it duplicates). Size ~20x1.5KB = ~30KB in the Postgres checkpointer (acceptable). Missing key on pre-existing checkpoints must be tolerated: `state.get("research_sources") or []` => every claim `unverifiable`/unverdicted rather than an error.
- **Unsourced claims:** judge every claim against the WHOLE corpus (all passages + the structured research fields), not only its own source. The prompt tells the model: `verified` only if a passage supports it, `contradicted` only if a passage directly conflicts (must cite), else `unverifiable`.
- **Search for no-source claims:** NOT needed to ship; deferred per CONTEXT. Flag in verification: report the % `unverifiable` on a real run; if very high, that is the trigger for the deferred search idea.

### Q3. Verdict placement

- **Current graph (20 nodes, `graph/builder.py:132-210`):** calibrator -> [discovery: signal_editor -> scout -> verify_candidates -> advocate -> editor_gate_1 -> chronicler] -> researcher -> verify_research -> {origin_story, problem, founder_bio, case_study, game, bonus, design} -> validate_sections -> qa -> editor_final -> publisher -> END. Brief mode skips the discovery block via `route_by_entry_mode`.
- **Recommendation: no new node.** Put the verdict step in the publisher, computed BEFORE `end_run(run_id)` (`publisher/__init__.py:67`, which pops the cost store, `cost.py:214-225`) so the call's cost lands in `cost_payload` written to Sanity/Convex. Concretely: at the top of `publisher()`, build `claim_rows` (extract + merge, existing logic factored into a helper) and run `await attach_verdicts(...)` inside try/except, THEN `end_run`, then the existing flow, then `insertBatch` with the verdict-enriched rows (`:225-232`). Failure => rows inserted without verdicts (neutral, non-blocking) and a warning log; never fails the run (matches the existing "claims are best-effort" comment at `:99-103`).
- **Why not a node:** a node would have to be added in `builder.py`, `lib/agent_wrapper.py:_INPUT_KEYS` (`:52` pattern), `api/runs.py:371-374` and `api/control.py:~412-418` (the `agentRuns:queueForRun` key lists, both the full and BRIEF sets), `pipelineTopology.ts`, `nomenclature.ts`, `declaredStateInputs.ts`, `AgentIOPanel.tsx`/`RunDetail.tsx`, plus tests that count 20 steps. Cost/benefit says no. (Trade-off to state to the user: no per-step visibility in Run Monitor and a "Restart from publisher" re-pays one Haiku call.)
- **Checkpoint/resume:** publisher is the last node; state is checkpointed before it. A re-run of publisher recomputes rows+verdicts deterministically from state and `insertBatch` is idempotent (deletes by `runId` first, `claimChecks.ts:61-67`). `research_sources` absent on an old checkpoint is tolerated (above).
- **insertBatch:** only callsite is `publisher/__init__.py:225` (plus tests). Add `verdict`, `verdictEvidence`, `verdictSources`, `verdictAt` as `v.optional` args and pass them through exactly like the Phase 35 fields (`claimChecks.ts:70-84`). `insertBatch` deletes-and-reinserts, so a re-run overwrites editor actions on that run's claims - already true today, unchanged.
- **Phase 42 endpoint interaction:**
  - `keepAsWritten`/`patch_claim`(text)/`remove`/`setStatus` all set a non-pending `status` and leave `verdict*` untouched => claim resolves. Good: verdict and editor action are separate (locked).
  - `markChanged` (called by `_reset_touched_claims`, `content.py:~190-230`) sets `status:'pending', changedSinceCheck:true` for every claim anchored to a touched block. Under the old gate that re-blocked; under the new predicates `changedSinceCheck===true` => NOT open/flagged (the agent verdict is stale because the sentence was edited). This also prevents a **deadlock**: a contradicted claim whose sentence the editor rewrote through a generic passage edit would otherwise re-open to `pending` but no longer resolve to a span to click. Residual risk: an unrelated edit in the same block silently clears a contradiction (block-level granularity, `_touched_block_indices`). Accept and document; the existing "Ask agent" revision flow is the re-check path. **Flag to user as a decision (see Open Questions #1).**
  - `replace-source` / `evidence/apply` set `keepAsWritten` terminal (`factcheck.py:318,599`) => resolved.
  - `_PIPELINE_SECRET_GUARDED_PATHS` (`lib/convex_client.py:67-79`) lists guarded claimChecks mutations; `insertBatch` is already there; no new mutation is required, so no change (if a new `setVerdict` mutation were added it MUST be added here - see `tests/test_brief_convex_guard.py:28`).

### Q4. Model routing and cost

- Routing: `lib/llm_config.py` `MODEL_BY_AGENT` / `SAMPLING_BY_AGENT` / `MAX_TOKENS_BY_AGENT`; `acomplete` looks up `MODEL_BY_AGENT[agent_id]` (`openrouter_client.py:~82,226`). Existing cheap id: `"anthropic/claude-haiku-4-5"` (scout/advocate/design, `llm_config.py:44-46`). Add `"fact_check": "anthropic/claude-haiku-4-5"`, sampling `{"temperature": 0.0, "top_p": 1.0}` (judgement, not creative; keep it with the existing "mechanical tier"), `MAX_TOKENS_BY_AGENT["fact_check"] = 8_000`.
- Precedent for an agent id outside the Prompt-Lab config set: `"revision"` (`llm_config.py:31,67`; used inline at `api/revision.py:304`). Follow it: inline system-prompt constant in `lib/claim_verdicts.py`, NOT in `ALL_AGENT_KEYS`/`prompt_versions` (avoids `test_config_loader.py` key-list pin and Prompt-Lab seeding). Note `config_loader._build_fallback_config` iterates `ALL_AGENT_KEYS` only.
- Cost tracking: `acomplete` -> `record_cost(run_id, agent_id, ...)` and `check_cap` (`openrouter_client.py:226-236`); `end_run` serializes the per-agent breakdown. A `CostCapExceeded` raised here would, inside the publisher's try/except, be swallowed - decide explicitly: re-raise `CostCapExceeded` (cap semantics) but swallow everything else. (Mirror how other agents treat it via `@agent_node`; the publisher block currently catches bare `Exception`, so the helper must re-raise it deliberately.)

## Common Pitfalls

### Pitfall 1: A hallucinated contradiction blocks publish
**What goes wrong:** Haiku marks a true claim `contradicted`; editor cannot publish until dismissing.
**How to avoid:** code-side downgrade to `unverifiable` when no valid cited `sourceIndexes`; prompt requires direct quote-level conflict; editor dismiss (`setStatus`) always clears (server gate counts only `pending`). Verification: fixture test for the downgrade.

### Pitfall 2: Lean projections drop verdict fields
**What goes wrong:** `WorkspaceStateProvider.tsx:253`, `useCurrentRun.ts:88`, `MyTasksScreen.tsx:300` rebuild claim rows field-by-field; if `verdict` is not added, predicates see "legacy" and tasks/stage silently show nothing while the server blocks - the exact client/server drift class from the 9-day outage.
**How to avoid:** add fields in all three + a test that feeds a contradicted row through each.

### Pitfall 3: Cost recorded after `end_run`
**What goes wrong:** a verdict call placed after `end_run()` (`publisher/__init__.py:67`) is invisible in the persisted cost payload and recreates an orphan cost store.
**How to avoid:** call before `end_run`; test asserts `fact_check` appears in `cost_payload`.

### Pitfall 4: `research` bloat
Do not store passages under `state['research']` (writers embed it). Use `research_sources`; declare it in `DispatchState` or LangGraph errors on the unknown key.

### Pitfall 5: Convex-first deploy ordering
See Q10. Wrong order silently yields zero claim rows (best-effort swallow).

### Pitfall 6: `CostCapExceeded` swallowed by the publisher's blanket except
Re-raise it explicitly from the helper (or catch narrowly) so cap semantics are preserved.

### Pitfall 7: Post-sign-off re-open hole (pre-existing)
Publish paths check sign-off presence only; `setStatus` back to `pending` or `markChanged` after sign-off does not revoke it, and now `pending` never blocks anyway. Out of scope; document in the contract so Phase 52 does not assume otherwise.

### Pitfall 8: Zero-claims interplay
`deriveFactCheckStage` returns `not-generated` for zero rows (`derivedState.ts:213`) - fine, but `ApprovalPanelContent` "no claims yet" copy and any "claims loaded?" spinner must not imply a block. `allSignedOff` true on empty is only safe because loading is `undefined` on the client (`useQuery` not yet resolved) - keep the loading guard (`RunScreen.gatesLoaded`, `:652`) so the gate never flashes green before claims load (Pitfall 5 in the file header of `claimChecks.ts`).

import { isOpenBlocking, isEditorFlagged } from './lib/claimGate'
export const allSignedOff = query({
  args: { runId: v.string() },
  handler: async (ctx, { runId }) => {
    const rows = await ctx.db.query('claim_checks')
      .withIndex('by_runId', q => q.eq('runId', runId)).collect()

      allSignedOff: blocking === 0, // zero claims => true; pending/legacy never block
    }
  },
})
