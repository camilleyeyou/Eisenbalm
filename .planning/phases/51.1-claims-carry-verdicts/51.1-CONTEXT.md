# Phase 51.1: Claims Carry Verdicts — Agents Clear Their Own Work - Context

**Gathered:** 2026-10-14
**Status:** Ready for planning
**Source:** In-session decisions with the user (2026-10-14) + ROADMAP.md Phase 51.1 block

<domain>
## Phase Boundary

The agents fact-check; the editor edits. Every extracted claim carries an agent-written verdict and the evidence behind it. Only contradicted claims block publish; only load-bearing claims the agents could not resolve are surfaced to the editor, in the sentence (Phase 51 surface, reused). An issue whose claims the agents cleared — or an issue with zero claims — needs no per-claim human action to publish.

Trigger (2026-10-14): the editor had to click "check" on all 234 claims of an issue before Publish enabled, with zero must-fix findings and "0 blocks" displayed. Same failure measured on 2026-08-06 (issue 999718: 117 claims, 58% with no sourceUrl, bare noun phrases like "2015", "Tameka Diaz").

</domain>

<decisions>
## Implementation Decisions

### Publish gate (LOCKED)
- Publish is blocked ONLY by claims with an agent verdict of `contradicted` that are still open (not fixed/dismissed by the editor).
- Unreviewed / `pending` claims NEVER block publish. No per-claim human click is required anywhere in the publish path.
- An issue with zero claims can publish (removes the `allSignedOff`-false-on-empty deadlock in `convex/claimChecks.ts`).
- Enforcement must be consistent client AND server side: `packages/pipeline/src/eisenbalm_pipeline/api/signoffs.py` (server gate) and every dashboard reader of `claimChecks.allSignedOff` (`lib/useCurrentRun.ts`, `app/(dashboard)/issues/page.tsx`, `components/AwaitingYouInbox.tsx`, Fact Check screen). Client/server gate drift caused a 9-day publish outage before (memory: phase34-retirement-half-done) — retire the old semantics everywhere in the same phase.
- The two-sign-off gate (Phase 34 `sign_offs`) remains; only the claim-side condition behind `facts-cleared` changes. Whether `facts-cleared` still needs a human sign-off click or becomes derived is for research/planning to recommend — default: keep the existing sign-off action, but it must be satisfiable without any per-claim action.

### Verdicts (LOCKED)
- Verdict values: `verified` | `contradicted` | `unverifiable`, plus agent evidence (short rationale + the source URL(s) used).
- Verdicts are written by an agent, not the editor. Editor actions on a flagged claim (fix text / dismiss) are recorded separately from the verdict.

### What the editor sees (LOCKED)
- `contradicted` claims: marked in the sentence and block publish.
- `unverifiable` claims: marked in the sentence ONLY when `importance === 'Load-bearing'`; Supporting/Incidental unverifiable claims stay silent. Never block.
- `verified` claims: not surfaced.
- No ledger/checklist of every extracted claim in the editor path. Surface reuses Phase 51's in-sentence marking / finding resolution — no new UI system.

### Verdict agent cost (LOCKED)
- Cheap model, ONE batched call per run checking all claims against already-fetched sources (Researcher/Tavily retrievals). No per-claim calls, no new web search fan-out unless research shows sources are absent for a large share of claims (then flag it, don't silently add search cost).
- Exact placement in the LangGraph (new node vs. extend existing fact_check/QA step) — research decides.

### Claim extraction (LOCKED)
- Extraction emits assertions that can be true or false, not bare noun phrases or numerals ("Rare Disease Day", "2015", "Tameka Diaz" must not be emitted as standalone claims).

### Legacy data (LOCKED)
- `claim_checks` rows written before this phase (no verdict field) must still load and resolve on every surface that reads them, and must NOT block publish of an issue in progress. Schema changes are additive/optional (Convex convention).

### Claude's Discretion
- Field names for verdict/evidence on `claim_checks` (follow camelCase + kebab-case literal conventions; update docs/API_CONTRACTS.md).
- Whether to keep `status` (pending/checked/skipped) for back-compat or derive it.
- Whether to fold verdicts into the existing Phase 33/42 findings stream or keep on `claim_checks` with the galley reading them.
- Model id choice for the "cheap model" (via OpenRouter, existing model-routing config).

</decisions>
