# Phase 22 Plan 02: Convex Config Contract Surface Summary

Fleshed out the four Phase-21 Convex stub tables with the function surface the config-externalization pipeline needs: per-agent settings (`agents` with new `top_p`/`max_tokens`/`description`), active prompts (`prompt_versions`), global settings (`pipeline_config`), and the dashboard `runs` superset (`create` + `setConfigSnapshot`). All write mutations are idempotent, mirroring the Phase-21 deterministic-upsert convention; `runs.create` inserts a schema-complete row with server-side `status="running"` + `startedAt=Date.now()`.

## What Was Built

**Task 1 — agents schema + agents.ts + pipelineConfig.ts (commit 9968187)**
- `convex/schema.ts`: added `top_p`/`max_tokens`/`description` optional columns to the `agents` table; `prompt_versions`/`pipeline_config` shapes left unchanged; frozen tables untouched.
- `convex/agents.ts`: `upsert` mutation (idempotent via `by_workspace_agentKey` `.unique()`, patch-or-insert) + `listForWorkspace` query (`by_workspace` `.collect()`).
- `convex/pipelineConfig.ts`: `upsert` mutation (idempotent via `by_workspace_key`, server-side `updatedAt`) + `getAll` query.

**Task 2 — promptVersions.ts + runs.ts (commit 6368e33)**
- `convex/promptVersions.ts`: `upsertActive` (v1-only seed semantics — existing row patches `content` + stays `isActive:true` without version bump; new row inserts `version:1, isActive:true`) + `getActive` query (filtered to `isActive===true`).
- `convex/runs.ts`: `create` (idempotent by `by_runId`; inserts `workspace_id`/`runId`/`triggerSource`/`triggeredBy` from args + server-side `status:"running"` + `startedAt:Date.now()`) + `setConfigSnapshot` (patch-by-runId, throws `Run not found: ${runId}` on miss) + a small `byRunId` read helper.
- `convex/_generated/api.d.ts`: regenerated to expose the four new namespaces (also restored the stale Phase-21 `users`/`workspace` namespaces that the blocked codegen had dropped).
