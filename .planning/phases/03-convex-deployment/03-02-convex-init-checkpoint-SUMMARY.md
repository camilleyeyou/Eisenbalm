## Deviations from Plan

Two deviations from the original 03-02 plan, both procedural rather than structural:

### Deviation 1 — `--configure` chose dev deployment, not production

**Plan assumption:** D-02 says "single `production` deployment only."

**Reality:** Convex's CLI auto-provisions a `dev` deployment when running `convex dev`. There is no `--production-only` flag for first-run setup; production deployments are promoted from dev via `npx convex deploy` from an authorized context (Plan 03-04).

**Resolution:** Accept the dev deployment as the single environment for Phase 3 evidence. Plan 03-04 will exercise `convex deploy` to push to a production deployment if/when Andrew creates one in the dashboard; for v1, the dev deployment is sufficient for CVX-05 verification (empty-table `useQuery` returns `[]`). Phase 4 (pipeline writes) will use whichever deployment is most appropriate at the time.

The locked decision D-02 ("single deployment") is honored in spirit — we have exactly one Convex environment.

### Deviation 2 — `convex/tsconfig.json` adjusted (removed `"types": ["node"]`)

**Discovered:** Running `convex dev --once` to regenerate `_generated/` after fixing the `convex.json` nesting failed typecheck with:

```
error TS2688: Cannot find type definition file for 'node'.
```

**Cause:** Plan 03-01's `convex/tsconfig.json` included `"types": ["node"]` but Convex functions run in a V8 isolate, not Node — `@types/node` is not a dep of the `@eisenbalm/convex` workspace and shouldn't be.

**Resolution:** Removed `"types": ["node"]` from `convex/tsconfig.json`. Committed as `fix(03-02): drop node types from convex tsconfig` (commit `5e55798`).

### Deviation 3 — Convex AI helper files written by `--configure`

**Discovered:** The interactive `--configure` flow prompted "Set up Convex AI files? Yes" and Andrew accepted. This produced:
- `convex/AGENTS.md` (Convex-specific AI guidelines)
- `convex/CLAUDE.md` (Convex-specific AI directive)
- `convex/skills-lock.json` (skill lockfile for Convex AI skills)
- `convex/.agents/skills/` (Convex AI agent skills)

**Resolution:** These are useful project-wide standards. Committed alongside `convex.json` (commit `ff374e3`). These do NOT conflict with the project's root `CLAUDE.md` (verified — the root CLAUDE.md still has its May 9 timestamp and Eisenbalm Dispatch content).

### Deviation 4 — `convex.json` not written by CLI

**Plan assumption:** `convex dev --once --configure` writes `convex.json`.

**Reality:** The CLI did not write `convex.json` in our nested-workspace scenario; it used internal defaults that placed `_generated/` at `convex/convex/_generated/` (nested).

**Resolution:** Hand-wrote `convex/convex.json` with `"functions": "./"`, deleted the nested `convex/convex/` directory, re-ran `convex dev --once` (codegen succeeded), confirmed `_generated/` now lands at `convex/_generated/`. This matches the 03-RESEARCH §Pitfall 6 hand-edit fallback exactly.
