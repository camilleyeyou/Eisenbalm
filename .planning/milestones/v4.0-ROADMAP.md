# Milestone v4.0: Dispatch Control v3 — The Editorial Workspace

**Status:** ✅ SHIPPED 2026-07-17
**Phases:** 40–50
**Total Plans:** 92

## Overview

Turned `apps/dispatch-control` from a set of desks that mirror the pipeline into an editorial product with an **issue** at its center — the machine retreats behind a "System Workbench" the operator visits only when something broke, and the editor never "triggers a pipeline." Eleven phases, foundation-first: Phase 40 inverts console routing to be issue-keyed (a run becomes a historical record *under* an issue) and adds an Issues home with four never-blended header state systems; Phase 41 collapses the Review Desk, Signal Desk, and Voice Pass nav items into **one Issue Workspace** with stage tabs 1–5, recomposing the shipped galley, voice-pass, and decision-rail/publish-gate work into Stages 2/4/5 with no loss of capability; Phase 42 lights up **Stage 3 Fact Check** — the milestone's only genuinely new stage — on the Phase 35 provenance substrate plus one new Researcher-emitted `importance` field, an affirmative "blank never means verified" coverage summary, a filterable claim table, and a provenance card reused everywhere; Phase 43 makes **My Tasks a derived projection** over open claims/findings/sign-offs (no new task store) and routes every reasoned action into one Decision log; Phase 44 adds the **universal 7-tab inspector** reachable from six surfaces, with the missing-expected-input diff as its headline diagnostic; Phase 45 makes **agent revision an editing verb** everywhere a passage is selected — direction chips, a claim-delta comparison card, and a per-issue cost guard; Phase 46 brings the v3.0 deferral due, growing the pipeline **18 → 20 nodes** with a Signal Editor agent and a deterministic `verify_candidates` gate; Phase 47 replaces the provisional Stage 1 with the full **Story & Brief** stage on real leads and verification records plus an editable Brief the writers draft from; Phase 48 makes **"Start from my brief"** a real second pipeline entry point that skips discovery and enters at the Researcher; Phase 49 lands **Roles** (Editor-in-chief vs Collaborator, six server-enforced gated actions, locked controls that explain themselves); and Phase 50 closes with the wide-but-shallow **Workbench rename + nomenclature pass** (Run Monitor → Run Details, Prompt Lab → Agent Instructions, Eval Center → Quality Tests, Registry → Editorial Memory) plus a failed-run recovery rail. Reuse discipline held throughout: the 1c design system (Phase 30), the two-sign-off publish gate (Phase 34), the eval commit gate (Phase 38), and the provenance substrate (Phase 35) were v4.0's foundation, not v4.0's work — every phase built strictly additively on them.

## Milestone Summary

**Stats:** 11 phases · 92 plans · 2026-07-14 → 2026-07-17 (4 days) · 406 commits · 556 files changed (+79,142 / −1,747).

**Track independence:** Phase 46 (Signal Editor + `verify_candidates`) was a self-contained backend track with no console dependency, sequenced before Phase 47 only because Stage 1 cannot render without its leads and verification records.

**Key Decisions:**

- **"Start from my brief" is in scope** as a real second pipeline entry point, not a stub — shipping a dead button in the primary CTA is worse than the phase it costs (Phase 48).
- **Publish drops typed confirmation** (reverses Phase 34) — exact preview + one click. The gate is the safety: Must fix = 0 ∧ Fact Check complete ∧ Voice approved current. Typed confirmation survives **only** for Mark Do-not-use. "Routine weekly approval is deliberately not scary."
- **Claim importance is emitted by the Researcher** — one field on each claim (Load-bearing / Supporting / Incidental). Not a new judge call, not derived post-hoc.
- **"Changed since check" is a block-level touched-counter**, not a re-verification requirement — matching the prototype, where an edit whose replacement text is *itself sourced* still increments the counter.
- **Sign-off revocation stays as Phase 34 built it.** The prototype does not revoke voice approval when a revision is applied, contradicting its own copy — that is a prototype bug. The sentence was ported, not the wiring.
- **Signal Editor + verify_candidates are in scope** — Stage 1 without them is a restyle of the old Signal Desk, and the design's whole trust story rests on the verification record (Phase 46).
- **Nomenclature rename is display-copy-only** — operator-facing terms change (Run Details, Agent Instructions, Quality Tests, Editorial Memory, deterministic check, step, Make active, Preview next run, Do not use, Must fix) while routes, enums, and node ids are preserved unchanged (Phase 50, tripwire-enforced).

**Issues Resolved:**

- Retired the run-keyed console model: routing inverted to issue-keyed, with a run reachable only as a historical record under an issue (ISS-02).
- Closed the v3.0 Signal Editor deferral (V3-DEF-02) — the pipeline grew 18 → 20 nodes with `signal_editor` before `scout` and `verify_candidates` between `scout` and `advocate`, checkpoint-resume verified across the new nodes (SGE-04).
- Closed the v3.0 roles deferral (V3-DEF-04) — RBAC landed with `users.role` server-enforced across exactly six gated actions (ROL-01..04); the "deferred to Phase 28" placeholder is retired.

**Technical Debt / Deferred:**

- Open human/visual UAT items persisted per phase in `*-HUMAN-UAT.md` / `*-VERIFICATION.md` (surfaced via `/gsd:audit-uat`).
- **Phase 50 — three open visual/UX items** tracked in the phase's deferred-items record, plus the **pre-existing duplicate-React-key nav warning** parked there (a prior condition, not introduced by v4.0).
- **Sanity removal** (V3-DEF-01), inline WYSIWYG galley editing (V3-DEF-03), and Suno + NotebookLM API automation (V3-DEF-05) remain deferred to future milestones.
