# Quick Task 260723-4a6: Test-readiness polish — skeletons, ⌘K palette, confirm dialogs, Gate-1 sign-off guard

**One-liner:** Instant-paint loading skeletons + a branded sign-in + per-route tab titles, a zero-dependency ⌘K command palette with a 1c confirm dialog replacing every `window.confirm()`, issue-stage keyboard shortcuts, and a server-side guard stopping a paused-or-failed run from receiving a bogus voice sign-off.

## What shipped

### Task 1 — First impressions
- `components/ui/Skeleton.tsx`: `Skeleton`/`SkeletonLine`/`SkeletonCard` shimmer primitives (Server Component, Tailwind `animate-pulse`).
- 11 new `loading.tsx` route segments (issues, issue workspace, my-tasks, run-monitor, prompt-lab, registry, finance, config, settings, eval-center, signal-desk) — each layout-matched so a stage switch or nav click paints instantly instead of blanking.
- Swapped the named high-traffic inline "Loading…" strings for skeletons in `ReviewDeskRunView.tsx` (top draft loader), `WorkspaceOutline.tsx` (`outline-loading`, testid preserved), `RunsTable.tsx`, `ReviewQueue.tsx`, `StoryBriefScreen.tsx`, `FactCheckScreen.tsx` (Coverage row), and `DecisionRail.tsx` (Hook card).
- Branded two-panel sign-in (`app/sign-in/[[...sign-in]]/page.tsx`): ink wordmark band (hidden below `md`) + Clerk `<SignIn>` mapped to 1c tokens via `appearance`, on `--color-rail` background.
- `app/icon.svg`: 64×64 ink square + vermilion diagonal slash favicon.
- `app/layout.tsx` metadata template `'%s — Dispatch Control'`; every dashboard route now sets a title via `export const metadata` (Server Component pages) or the new `components/ui/DocumentTitle.tsx` client helper (client-only pages, and the per-stage "Issue {n} · {Stage}" title in the workspace frame).

### Task 2 — Command palette, confirm dialog, stage shortcuts
- `components/ui/ConfirmDialog.tsx`: `ConfirmProvider` + promise-based `useConfirm({title, body, confirmLabel, cancelLabel, tone})` — 1c-styled modal (`z-[70]`), Escape/backdrop-click resolve `false`, focuses Confirm on open.
- `components/CommandPalette.tsx`: `CommandPaletteProvider` + `useCommandPalette()` — global `⌘K`/`Ctrl+K` listener, overlay (`z-[75]`) with arrow-key nav, Enter-to-navigate, scoring (startsWith > includes). Sources: `lib/nav.ts`'s canonical route list, `api.issues.listForWorkspace` (+ 5 stage sub-entries once a query is typed), `api.runs.listRecentForWorkspace` — no new Convex functions.
- Both providers mounted in `(dashboard)/layout.tsx` as client-provider siblings inside `OnboardingProvider`; the layout itself stays a Server Component.
- Masthead ⌘K chip added to the right cluster (`hidden md:flex`).
- All 5 `window.confirm()` sites swapped to `await confirm(...)`: `ReviewDeskRunView.tsx`'s 3 unsaved-edit guards (switchViewMode/handleChipSelect/handleEditSection), `RecoveryRail.tsx`'s restart confirm, `RerollButton.tsx`'s re-roll confirm, `InspectorFooter.tsx`'s restart confirm, and `AgentPromptEditorView.tsx`'s dirty-guard confirm (`requestStopEditing`) plus its fire-and-forget agentKey-switch heads-up (reset proceeds regardless of the operator's answer, matching prior behavior).
- Issue workspace stage tabs (`issues/[issueNumber]/layout.tsx`) gained bare digit `1`-`5` shortcuts — guarded against typing targets (input/textarea/select/contenteditable) and any modifier key — plus a faint digit hint rendered in its own `<span>` alongside each tab label.

### Task 3 — Gate-1 correctness
- `signoffs.py`'s `sounds-human` branch gained a `run_not_reviewable` guard (named `run_status` to avoid shadowing the imported `status` module) immediately after the existing role gate: `run_status == "failed" or (run_status == "awaiting-review" and not completed_at)` → 409. Additive to the existing `no_sanity_issue` (F5) guard; does not touch `facts-cleared`.
- `test_signoffs_endpoints.py`: `_run()` fixture now carries `completedAt` (a genuine final-review run); 2 new tests assert 409 `run_not_reviewable` for a paused-at-Gate-1 run and a failed run, and that `signOffs:record` is never called in either case.
- Verified (not re-implemented): `RecoveryRail.tsx`'s already-shipped paused-run rendering ("Paused for your decision" + `/signal-desk` restart link) survived the ConfirmDialog swap — its existing regression test in `RecoveryRail.test.tsx` still passes.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 3 - Blocking] Wrapped 3 additional test files in ConfirmProvider/CommandPaletteProvider beyond the 2 the plan named**
- **Found during:** Task 2, after adding `useConfirm()` to `RerollButton.tsx` and `InspectorFooter.tsx`
- **Issue:** `useConfirm()`/`useCommandPalette()` throw when rendered outside their provider (per plan spec — mirrors `OnboardingProvider`'s existing throw-if-unmounted shape). Three test files render these components directly or transitively without a provider ancestor and would have failed the build's test gate: `__tests__/InspectorPanel.test.tsx` (mounts `InspectorFooter` internally, 12 tests), `__tests__/runControl.test.tsx` (renders `RerollButton` directly, 8 tests), `__tests__/promptVersionOrigin.test.ts` (renders `InspectorFooter` 3 times via `React.createElement`), and `__tests__/Masthead.test.tsx` (13 `render(<Masthead />)` calls, once the masthead's ⌘K chip called `useCommandPalette()`)
- **Fix:** Added a local `render*()` helper wrapping the target component in the relevant provider(s) in each file; replaced the bare `render(...)` calls
- **Files modified:** `__tests__/InspectorPanel.test.tsx`, `__tests__/runControl.test.tsx`, `__tests__/promptVersionOrigin.test.ts`, `__tests__/Masthead.test.tsx`
- **Verification:** `pnpm --filter dispatch-control test` green (1087/1087)
- **Committed in:** 91a3b17 (Task 2 commit)

**2. [Rule 1 - Bug] FactCheckScreen.test.tsx's loading-state assertion invalidated by the skeleton swap**
- **Found during:** Task 1, first full test run
- **Issue:** `getByText(/loading/i)` no longer matched once the "Loading…" string became a text-free `<SkeletonLine>` — the assertion tested an implementation detail (text), not the actual behavior (a loading indicator renders, never a fake verified state)
- **Fix:** Added `data-testid="fact-check-coverage-loading"` to the skeleton wrapper in `FactCheckScreen.tsx`; updated the test to query by that testid, keeping the `queryByText(/verified/i)`/`queryByText(/complete/i)` "never fake-verified" assertions unchanged
- **Files modified:** `app/(dashboard)/issues/[issueNumber]/fact-check/FactCheckScreen.tsx`, `__tests__/FactCheckScreen.test.tsx`
- **Verification:** `pnpm --filter dispatch-control test` green
- **Committed in:** e638df4 (Task 1 commit)
