<objective>
Fix `verify_candidates` killing every Scout candidate (production run interrupted at editor_gate_1 with `all-candidates-killed`).

Root cause (confirmed live against Tavily): the langchain_tavily wrapper is built with max_results=10 and `ainvoke` ignores the per-call cap, so `web_search(name)` returns ~10 results for almost any query — a fabricated org ("Zyxwvut Quiet Library Acoustics Trust of Lower Vermont") gets 10 unrelated generic results. `_obscurity_press_scan` returns `len(results)`, and `_apply_kill_rule` kills at >=9, so essentially every candidate is killed as "not obscure". Secondary: `_check_domain_live` returns False (definitive kill) on ANY 4xx, but small-org sites behind Cloudflare/WAF routinely return 401/403/429 to bots.

Purpose: restore the D-12 conservative posture (false negatives OK, false positives never) so real runs reach Advocate with candidates.
Output: patched verify_candidates.py + new regression test file; full pipeline suite green.
Deployment (push to master → Railway) is handled by the orchestrator, NOT this plan.
</objective>
