# Quick 260718-00i: Finish Phase 34 studio-bypass-retirement — collapse legacy publish surface Summary

Closed the traced production incident from the 2026-07-17 whole-dashboard UI audit: gated the
second ungated publish path (`POST /issues/{run_id}/publish-manual`) on the same two-sign-off
check `publish_issue` enforces, ported "Schedule for later" onto the Approval-stage DecisionRail,
and retired the legacy `/run-monitor/runs/[runId]/review` panel (stale `claimChecks.allSignedOff`
gate, zero sign-off controls) into a server redirect to `/issues/[n]/approval`.

## What Was Built

**Task 1 — Two-sign-off gate on `publish-manual` (RED test first)**
Added `test_publish_manual_requires_both_signoffs` to `test_publish_bridge.py`, wired an
Editor-in-chief claim + empty `signOffs:activeByRunId` response, and ran it in isolation against
the *unmodified* handler: it failed with `200` (the current handler resolves the issue, audits
`publisher.manual_restart`, and schedules `_run_publisher` with zero sign-off check) — confirming
the gate was genuinely absent, not a test artifact. Then inserted the identical
`missing`/`missing_signoffs` 409 block from `review.py:118-133` into `control.py::publish_manual`,
placed after the 404 issue-lookup and before the audit/schedule call ("nothing silent" — a
blocked publish is neither audited nor scheduled). Repaired the two pre-existing tests
(`test_editor_invokes_publisher_and_audits`, `test_sentinel_regression_resolves_editor`) to wire
both sign-offs active so they still exercise the normal 200 path. Full pipeline suite: 700 passed,
38 skipped (pre-existing/unrelated).

**Task 2 — Port `SchedulePublishDialog` onto the Approval surface**
Copied the legacy dialog (same `scheduleIssue`/`ReviewApiError` calls, same `schedule_in_past`
branch) into `review-desk/[runId]/_components/`, restyled from Tailwind `neutral-*` classes to
the rail's `var(--color-*)` CSS-variable tokens — behavior identical, no scope drift. Wired it
into `DecisionRail.tsx`'s Actions section as a secondary "Schedule for later" button gated by the
exact same `publishDisabled` derivation Publish uses, so the two enable/disable together. Kept as
a separate component (never inlined into `DecisionRail.tsx`) so the `<input type="datetime-local">`
never lands inside the file the `publishNoTypedConfirm` tripwire source-scans.

**Task 3 — Retire the legacy publish panel**
Extended `legacyRedirectTarget`'s surface union to include `'approval'` (maps to
`issueApprovalHref`), then gutted `run-monitor/runs/[runId]/review/page.tsx` into a pure server
redirect mirroring `voice-pass/[runId]/page.tsx` verbatim — resolves `runId -> issueNumber` via
`pipelineRuns.byRunId`, redirects to Approval (falls back to `/issues` when unresolvable, never a
run-keyed URL). Re-grepped for zero remaining importers, then deleted `ReviewDecisionPanel.tsx`
and its legacy `SchedulePublishDialog.tsx` sibling. Repointed `ReviewQueue.tsx`'s "Review →" CTA:
extracted a per-row `AwaitingReviewRow` component that resolves its own `issueNumber` via
`pipelineRuns.byRunId` (the `runs` table has no `issueNumber` field) and links to
`issueApprovalHref`, falling back to the (now-redirecting) legacy URL while that query loads.
Trimmed `publishNoTypedConfirm.test.ts` to the two surviving publish surfaces (`DecisionRail`,
`PublishPreviewDialog`) — removed the `REVIEW_DECISION_PANEL` const, its file-existence check,
and its two dedicated `it()` blocks. Left `ClaimsChecklist.tsx`/`PreviewIframe.tsx` in place
per plan (orphaned-but-harmless, out of scope — they have their own test coverage). Updated
`reviewClient.ts`'s `publishIssue`/`scheduleIssue` JSDoc from the stale pre-Phase-34
`claims_not_signed_off` copy to the current `missing_signoffs` contract — doc-only, no behavior
change to `_reviewFetch`'s reason-parsing or any function signature.
