<objective>
Fix the Issue Workspace outline sidebar that spins "Loading outline…" forever on a paused-at-Gate-1 / otherwise contentless run. The `WorkspaceStateProvider` getDraft effect sets `draft = null` on ANY failure, and `sectionStates = draft ? … : undefined`; `WorkspaceOutline` shows "Loading outline…" whenever `sectionStates === undefined`. So a DEFINITIVE no-content 409 (`ContentPatchError`, `reason === 'no_sanity_issue'`) is indistinguishable from still-loading → perpetual spinner.

Distinguish THREE draft outcomes instead of two:
1. still loading → keep "Loading outline…" (`sectionStates` undefined).
2. loaded with content → the real outline (unchanged).
3. loaded but definitively contentless (`no_sanity_issue` 409) → an HONEST resolved empty state, never perpetual loading.

Purpose: The main Approval panel already renders "Paused at the story decision" for this exact run (quick 260719-w6o); the outline sidebar must stop being the one inconsistent, perpetually-spinning surface.
Output: One new RED-gated test file; a new `draftContentAbsent` provider signal scoped strictly to the `no_sanity_issue` reason; a dedicated outline empty state.
</objective>

<design_decision>
CHOSEN: Option A — a distinct, self-describing provider signal `draftContentAbsent: boolean`.

Justification (required):
- Option B (feed an empty derivation so every section shows 'not-generated') is exactly the "wall of not-generated from a failed load" the provider's WSP-07 design comment (L24-28, L59-64) DELIBERATELY guards against. Even scoped to `no_sanity_issue`, B produces nine "— not generated" rows that read as REAL editorial state (as if the sections were attempted and skipped) — misleading for a run that never got past Gate 1.
- Option A renders a single, honest sentence ("No sections yet — this run paused before generating content.") that reads consistently with the Approval panel's "Paused at the story decision," and can never be mistaken for per-section "not generated" data. It is also less code than reworking the derivation path.

SCOPING RULE (crucial): `draftContentAbsent` is set true ONLY when `e instanceof ContentPatchError && e.reason === 'no_sanity_issue'`. Every other error (network blip, generic Error, any other reason) leaves it false → the outline STAYS on "Loading outline…" (original WSP-07 intent intact). It is reset to false at the start of every new run's fetch so a prior run's absent-state never leaks.
</design_decision>
