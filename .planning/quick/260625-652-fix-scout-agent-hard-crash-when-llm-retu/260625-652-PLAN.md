<objective>
Fix the Scout agent hard-crash that occurs when the LLM returns zero charity candidates (observed in Railway: run 0b9dba62 failed with "ScoutBatchOutput ... Scout must surface at least 1 candidate (got 0)").

Purpose: A transient empty-candidate response from the model currently crashes the ENTIRE weekly pipeline run because the `_at_least_one` field_validator raises a `ValidationError` *inside* the OpenAI SDK's `model_parse_json` step — escaping `acomplete`'s corrective-retry path and tripping the blind `except Exception` that re-sends identical messages, fails again, and propagates a crash through `@agent_node`. The fix makes empty-candidate handling explicit and recoverable in `scout()`, with one corrective retry and a clear failure surface if recovery is impossible.

Output: An updated `scout.py` (validator removed, corrective-retry added, comments corrected) and extended `test_scout.py` covering both the recovery and the hard-fail paths.
</objective>
