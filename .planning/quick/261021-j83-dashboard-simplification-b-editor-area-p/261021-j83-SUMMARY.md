# Quick 261021-j83: Dashboard simplification B, editor area plus /admin hub

The app now has two doors. The editor area (`/`, `/s/[section]`, `/archive`, `/sign-in`) has no sidebar. One `Admin` link leads to `/admin`, a flat hub of 7 items. Every dead console surface is deleted and its URL redirects.

## Commits
- `10441990` Task 1: front door Start issue and Hold/Release, Admin to `/admin`, `/archive`
- `34c55700` Task 2: `/admin` hub and slim shell, 9 admin pages moved under `/admin/*`
- `c742422b` Task 3: deletions, `next.config` redirects, resolver cleanup, test sweep

## What changed
- **Front door:** `StartIssueButton` is enabled for footer kinds none/published/failed or when the issue is held. It uses an inline confirm and calls `triggerRun({})` once. A 409 maps to a plain message plus the server detail. `HoldControl` shows for every role and is hidden for none/loading/published. Hold stops the run only if asked and tolerates a cancel failure. Release is one click. The footer no longer links to charity choice, fact-check or approval.
- **Archive:** `/archive` replaces `/issues`. The start/create/scheduled panels and the ensure/repetition effects are gone. The current issue's row opens `/`. A published row opens the live issue via `NEXT_PUBLIC_WEB_PREVIEW_BASE`. Held rows keep Release.
- **Admin:** `ADMIN_ITEMS` (Finance, Charities, Runs, Agent instructions, Quality tests, Automation, Settings) replaces the sidebar nav. `app/admin/layout.tsx` is a slim bar with the original provider order kept. The runs tab bar now keeps Graph from also lighting up Runs. The command palette lists the front door, archive, admin items and recent runs.
- **Deleted:** the whole `app/(dashboard)` group, the Masthead/sidebar/drawer/inbox, onboarding, decision-log, revision, and eight dead libs.
- **Redirects:** `next.config.ts` has 307 redirects straight to the final page. `nextConfigRedirects.test.ts` checks the mapping, no chains, and that every destination exists on disk.

## Deviations from Plan
1. **[Rule 1 - Bug] Legacy Gate-1 recovery linked to a retired screen.** `RecoveryRail` linked "Restart from this step" to `/signal-desk`, which now redirects to `/`. It now shows a disabled control and the text "This older run paused to choose a charity. Stop it, then start a new issue from the front page." Tests updated.
2. **[Rule 1 - Bug] Stale verification-record disclosure removed.** The archive's "Verification record" (Facts cleared by / Voice approved by) would read blank for every row, since sign-offs are gone. I removed it and deleted the now-orphaned `RecentlyPublishedRow`, so the plan's "move RecentlyPublishedRow" was not carried out. The archive has no per-row N+1 subscription now.
3. **[Rule 3 - Blocking] Task 2 left tests failing at its commit.** The old `(dashboard)` group was still present at that point, so I deleted `issues/[n]/runs/[runId]/page.tsx` and kept a temporary nav shim to keep the build green. Task 2's targeted tests and the build passed. The shim was removed in Task 3, and the full suite is green at the Task 3 commit.
4. `helpCopy.publish` text changed ("read and edit, not publish") to match D-6. `RunControlBar`, `ReviewQueue` and `RunDetail` links to the issue now point to `/`.
5. The `lib/derivedState.ts` task title "Choose the charity to continue" is left as is. `deriveTasks` is consumed only by tests now; its hrefs all point to `/`.
