<objective>
Mirror `pipelineRuns.status` into the dashboard `runs` table so that failed,
complete, and awaiting-review runs land terminal in BOTH tables — fixing the
un-cancellable "zombie" run and the one-at-a-time 409 gate that blocks new runs.

Purpose: `convex/schema.ts` (line 246) documents the intended behavior verbatim
— `status: v.string(), // mirrors pipelineRuns.status; updated alongside it` —
but the mirror was never wired. `pipelineRuns:updateStatus` patches ONLY the
`pipelineRuns` row. The only terminal writes to `runs` were the cancel/cost-cap
paths (writing 'cancelled'); the agent-crash 'failed' path and the happy
'awaiting-review'/'complete' path never touched `runs`. So after a Scout crash,
`pipelineRuns.status='failed'` but `runs.status` stayed `'running'` → zombie →
409 gate blocks all new manual runs.

Output: One edited Convex mutation handler. Pipeline Python is UNCHANGED — the
centralized Convex mirror covers every transition site at once.

    .query('runs')
    .withIndex('by_runId', q => q.eq('runId', runId))
    .first()
  if (!run) throw new Error(`Run not found: ${runId}`)

    status,
    ...(completedAt !== undefined ? { completedAt } : {}),
