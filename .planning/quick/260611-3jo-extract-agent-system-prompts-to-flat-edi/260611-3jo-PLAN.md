<objective>
Extract each LLM agent's **static system-prompt prose** into flat, editable
`packages/pipeline/prompts/<agent-id>.md` files plus a `lib/prompts.py` loader,
so a non-technical editor can revise prompts via GitHub PRs without touching
Python. This is a PURE behavior-preserving refactor — zero prompt-wording
change, zero behavior change. The full pytest suite (which includes exact
substring and byte-equivalence assertions on prompt text) MUST stay green.

Purpose: decouple prompt prose (an editorial artifact Andrew/Ghislain own)
from Python plumbing, mirroring the existing precedent where the QA judge
already loads its system prompt from `agents/qa/rubric.md`.

Output: 11 prompt `.md` files (one per static system prompt; bonus has 3
branches), a loader module, a packaging update so `prompts/` ships on Railway,
each agent rewired to load+substitute, and a plain-voice Andrew guide.
</objective>

<scope_note>
**In scope (agents with their OWN static system prose):** scout, advocate,
calibrator, editor (two prompts: gate-1 + editor-final), researcher, game,
bonus (three branch prompts: bigBudget / jingle / specAd), design.

**Explicitly EXCLUDED (do NOT create files for these):**
- **origin_story, problem, founder_bio, case_study** — these 4 narrative
  writers have NO own system prose. Their system message is assembled by
  `lib/voice.build_section_writer_prompt(...)`, which is EXCLUDED from this
  pass (locked decision #2). Their `SECTION_GUIDANCE` / `GUIDANCE_*` /
  `STRUCTURE_CONTRACT` strings are user-message data plumbing (locked
  decision #1) and STAY in Python. Leave these 4 files untouched.
- **lib/voice.py / VOICE_CONSTRAINTS / UNIVERSAL_CORE / JESSE_PERSONA_BLOCK**
  — excluded (locked decision #2). Agents continue importing and interpolating
  these in Python. They are runtime tokens substituted INTO the loaded
  templates, not moved.
- **publisher** — no LLM prompt (locked decision #3).
- **qa** — its system prompt is ALREADY extracted to `agents/qa/rubric.md`
  and loaded via `_load_rubric()`. It already satisfies the goal. Do NOT
  move it to `prompts/qa.md`: `tests/test_qa_judge_narrator.py` asserts
  byte-equivalence against `_load_rubric()`, and moving the file risks
  breaking that path for zero benefit. Note it in the README as
  "already editable at agents/qa/rubric.md". (If you want consistency you
  MAY leave a `prompts/qa.md` that is just a pointer note — but do NOT
  rewire judge.py.)
- **chronicler** — see Task 4 decision gate. Its LLM system prompt is
  DYNAMICALLY composed (calibrator-set `style_brief["voice"]` + a local
  `WINNER_AUTHORITY_PREAMBLE` + optional narrator rubric/samples + a static
  role-instruction block), then post-processed with
  `.replace("\n\n\n", "\n\n")`. Only the static role-instruction block and
  `WINNER_AUTHORITY_PREAMBLE` are candidate prose, and `test_chronicler.py`
  asserts several exact substrings ("WINNER AUTHORITY", "authoritative",
  "supporting rationale only", "<winner> is the selected charity"). Extracting
  these without touching the fragile newline-collapse composition is high-risk
  for near-zero editorial value. **DEFAULT: skip chronicler this pass and note
  it in the plan/README.** Only extract if Task 4's byte-equivalence probe
  proves trivially safe.

**Token convention (locked decision #4):** keep the CURRENT f-string tokens as
single-brace `{token}` placeholders in the `.md` files. Substitute with
`str.replace("{token}", value)` (NOT `str.format`), so any literal braces in
the prose (e.g. design has none; game's FORBIDDEN list has none; JSON examples
elsewhere are in USER messages, not these system strings) survive untouched and
you never have to escape `{{`/`}}`. Verify per-agent there are no literal
braces in the extracted system string before choosing `.replace`; if a literal
brace exists, still use `.replace` (it is brace-agnostic). This reproduces the
current strings BYTE-FOR-BYTE.
</scope_note>
