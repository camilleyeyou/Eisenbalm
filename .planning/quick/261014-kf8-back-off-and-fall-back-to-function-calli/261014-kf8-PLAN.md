<objective>
Stop pipeline runs failing on OpenRouter 400 `Grammar compilation rate limit exceeded` (Anthropic shared org, 50 compilations/min, `is_byok: False` — we cannot raise the limit).

Root cause: `acomplete()` uses `llm.with_structured_output(response_format, include_raw=True)`; langchain-openai 1.2.1 defaults to `method="json_schema"` (strict) → Anthropic compiles a grammar per schema. The existing invoke-error retry fires immediately with the same strict runnable, lands in the same rate window, and the agent fails.

Fix: in the structured path only, on a grammar-rate-limit error rebuild the runnable with `method="function_calling"` (non-strict tool use, no grammar compilation) and retry; on other rate limits, sleep a jittered backoff then retry; cap rate-limit retries at 2.

Output: patched `openrouter_client.py`, new test file, commit, push to origin master (Railway deploy).
</objective>
