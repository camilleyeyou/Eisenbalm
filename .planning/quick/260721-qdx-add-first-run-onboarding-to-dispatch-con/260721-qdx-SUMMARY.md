## Accomplishments

- Additive `user_onboarding` Convex table (sibling of `users`, keyed by `clerkUserId`) + `byClerkUserId` query and `completeTour`/`dismissCard`/`dismissStageHint` mutations, mirroring `convex/users.ts` conventions exactly (file-local `DEFAULT_WORKSPACE_ID`, `by_clerkUserId` index, upsert-on-first-mutation-call pattern).
- `OnboardingProvider` — a shell-level context (mounted once in `app/(dashboard)/layout.tsx`, inside `InspectorProvider`, a sibling of and fully independent from the Issue Workspace's `WorkspaceStateProvider`) wrapping a single stable `useQuery(api.userOnboarding.byClerkUserId, ...)`. A one-shot `useRef` guard auto-opens the tour exactly once per mount, only once the query has genuinely resolved (never while `undefined`/loading) and only when the row is missing or `tourCompletedAt == null`.
- `OnboardingTour` — a 5-step in-house dim-backdrop overlay (no new npm dependency): nav groups → masthead inbox → My Tasks → the weekly loop (with the Collaborator publish caveat) → How to use. `Skip tour` and the final `Next`/`Done` both call `completeTour` then close; Esc closes (= skip).
- `StartHereCard` — dismissible "Start here" card mounted at the top of Issues home, mapping all 5 stages (Story/Draft/Fact Check/Voice/Approval) to their `issueRouteResolver` hrefs for the current in-progress issue (plain text, never a dead `/issues/null/...` link, when none is in progress), plus "Take the 1-min tour" and Dismiss/✕ (both call `dismissCard`).
- `StageHintStrip` — a one-time dismissible hint strip mounted above the stage canvas in `issues/[issueNumber]/layout.tsx`, gated on the frame's already-computed `currentStageSegment` (renders nothing on the bare overview route). Reads onboarding state only via the shell-level `useOnboarding()` context and fires its own `dismissStageHint` mutation — proven, via a comment-stripped source-scan test, to never reference `useWorkspaceState`/`setPanelContent`.
- `ReplayTourButton` — a small client island added to `how-to-use/page.tsx` (which stays a Server Component) calling `launchTour()`.
- All dismissal/completion state is per-Clerk-user, Convex-backed, and survives re-login (no localStorage).

## Decisions Made

- `onboardingCopy.ts`'s `StageSegment` type is a standalone exported literal union (`'story' | 'draft' | 'fact-check' | 'voice' | 'approval'`), structurally identical to (but not importing) the private `StageSegment` type already defined in `issues/[issueNumber]/layout.tsx` — TypeScript's structural typing lets `currentStageSegment` flow into `StageHintStrip`'s prop without a shared import, avoiding a cross-cutting refactor of the layout file's private type.
- `StageHintStrip`'s two dismiss affordances ("Dismiss" text button, "✕" icon button) were given distinct accessible names (`"Dismiss"` vs. `aria-label="Dismiss hint"`) rather than both being "Dismiss" (as `StartHereCard`'s pair are) — this was Claude's discretion within the plan's "Dismiss/✕ close" spec, chosen to keep the strip's test queries unambiguous; `StartHereCard`'s pair intentionally share the accessible name "Dismiss" per the plan's literal `[Dismiss] ✕ close` card shape, and its test asserts on both via `getAllByRole`.
- `StageHintStrip` accepts `issueNumber` as a prop (per the plan's call-site signature) but does not use it in the `dismissStageHint` mutation call — dismissal is per-stage-per-user, not per-issue-per-stage, matching the `user_onboarding.dismissedStageHints` schema (a flat array of stage segments). The prop is threaded onto a `data-issue-number` attribute so it isn't a dead unused parameter.

- **Issue:** `FrameChromeCostReadout.test.tsx`, `WorkspaceApprovalPanelLoop.test.tsx`, `WorkspaceContextPanelSlot.test.tsx`, `WorkspaceDraftLoadLoop.test.tsx`, `WorkspaceLayout.test.tsx`, and `WorkspaceOutlineEmptyState.test.tsx` all render `IssueWorkspaceLayout` in isolation (without the dashboard shell's `OnboardingProvider`, which is mounted one level up in `app/(dashboard)/layout.tsx`). None of these 6 files make any assertion about onboarding — the mock is a harmless, isolated no-op that lets each file continue testing its own actual subject (cost readout, context-panel slot, draft-load loop, stage tabs, outline empty-state, approval-panel loop) unaffected.
- **Files modified:** the 6 test files listed above
