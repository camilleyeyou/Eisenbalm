<objective>
Make the Publisher's Vercel deploy-hook call resilient. Today a transient HTTP 429 (or 5xx) from the deploy hook turns into an unhandled `httpx.HTTPStatusError` that kills the publisher task AFTER the PDF upload + Sanity patch but BEFORE the Convex finalization (status='complete' + publisher-deploy event). The run is left un-finalized in Convex and no front-end rebuild fires.

Three coordinated changes:
1. Add bounded retry/backoff for TRANSIENT failures (429 + 5xx) inside `trigger_vercel_deploy`, honoring `Retry-After` when parseable. Non-transient 4xx still raise immediately. After exhausting retries, raise (caller decides fatality). Happy path return shape unchanged.
2. In `_run_publisher`, make the deploy NON-FATAL: wrap in try/except, on final failure log a warning and set a sentinel `deploy_response = {"error": "<message>"}`, then continue.
3. GUARANTEE finalization: the Convex `pipelineRuns:updateStatus -> complete` write and the `publisher-deploy` event always execute (when run_id is not None); the event payload carries the sentinel so the failure is observable. No Convex schema change — reuse the existing `publisher-deploy` literal.

Purpose: a missed deploy hook (not user-visible thanks to ISR 60s) must never leave a run un-finalized.
Output: resilient deploy + guaranteed finalization, fully unit-covered with patchable (non-sleeping) backoff.
</objective>
