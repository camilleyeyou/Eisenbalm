<objective>
Implement the LOCKED HYBRID theme model (09-CONTEXT.md) so the Phase 9 dark redesign actually renders.

Today the dark house palette in `globals.css :root` (`--color-bg: #0C0B0A`, `--color-text: #F0EAD9`) is overridden by inline `<style>` injection: the root layout injects `serializeThemeCss(null)` and the issue layout injects `serializeThemeCss(issue.theme)`, both of which emit light `--color-bg`/`--color-text` (BRAND_DEFAULTS / per-issue light values). Because those inline styles load AFTER globals.css, the light values win the cascade and every page renders light.

HYBRID model: per-issue theming drives ONLY the accent layer (`--color-primary` / `--color-accent`). The `--color-bg` / `--color-text` are HOUSE STYLE, owned by `globals.css :root`, and must NOT be emitted by injection.

Purpose: Make the deployed dark redesign visible on the live site without weakening the security contract.
Output: A surgical edit to `apps/web/lib/theme.ts` that stops emitting `--color-bg` / `--color-text` from the two injection paths and the fallback path, while keeping `--color-primary`, `--color-accent`, `--font-display`, `--font-body`.

NON-NEGOTIABLE (CLAUDE.md + 09-CONTEXT.md LOCKED): Do NOT weaken theme.ts security. Keep ALL hex validation, FONT_WHITELIST, WCAG/contrast logic, and setProperty-only structure intact. This is a removal of two output lines per code path — NOT a refactor of the theme engine. `resolvePalette`, `validateHex`, `validateFont`, `passesWcagAA`, `contrastRatio`, BRAND_DEFAULTS, and all comments stay exactly as they are (validation/comment references to bg/text MAY remain).
</objective>
