# Quick 260722-v01: Mobile Responsiveness + Flagged Audit Fixes Summary

Closed all nine "Flagged, NOT fixed" items from the 2026-07-22 dispatch-control
layout audit: a below-md off-canvas nav drawer + responsive padding + scrollable
stage tabs, a graph/AutoPublishBanner height-chain fix, severity-grouped My
Tasks, one consolidated Story-stage Decision log (was up to ~11 duplicates), a
body-portaled viewport-clamped HelpTip, capped Registry/Finance tables, deletion
of dead ClaimsChecklist code, an additive `listRecentForWorkspace` Convex query
(deployed) wired into RunsTable, a fix for the Draft-stage "Show preview"
collapsed-iframe bug, and a full class-token migration of the Run Monitor
surfaces onto the app's `var(--color-*)` design-token system.

## What Was Built

### Task 1 — Mobile responsiveness + graph/banner height chain

- **`SidebarNav.tsx`** (new): the entire nav content (NAV_GROUPS mapping,
  NavLink helper, NAV_PINNED, RoleIndicator) extracted out of `AppSidebar.tsx`
  so it can be rendered identically by both the desktop `<aside>` and the new
  mobile drawer. Accepts an optional `onNavigate` closer callback.
- **`AppSidebar.tsx`**: `<aside>` is now `hidden md:flex` (removed from flow
  below md, unchanged 210px in-flow at md+); its only child is `<SidebarNav />`.
- **`MobileNavDrawer.tsx`** (new): a self-contained fixed hamburger
  (`left-[8px] top-0 z-[60]`) + off-canvas drawer (`fixed left-0 top-[52px]
  z-50 h-[calc(100%-52px)] w-[240px]`) + backdrop (`z-40`). Escape, backdrop
  click, and route change all close it; the first link is focused on open.
  Mounted as the first child of `app/(dashboard)/layout.tsx`, **not** inside
  `Masthead.tsx` (Masthead.test.tsx mocks only `convex/react`,
  `@convex/_generated/api`, `@clerk/nextjs` — importing usePathname/useRole
  there would have broken that mock surface). The layout stays a Server
  Component.
- **`Masthead.tsx`**: header gained `pl-[52px] md:pl-[22px]` (className only)
  so the fixed hamburger never overlaps the wordmark below md.
- **`(dashboard)/layout.tsx`**: `<main>` is `flex flex-1 flex-col overflow-y-auto
  p-4 md:p-6` (was `flex-1 overflow-y-auto p-6`); the AutoPublishBanner wrapper
  gained `shrink-0`.
- **`run-monitor/layout.tsx`**: shell root `flex h-full flex-col` → `flex
  min-h-0 flex-1 flex-col`, completing the height chain so the graph page's
  own `h-full` chain resolves against the space remaining under the banner
  instead of overflowing by the banner's height.
- **`issues/[issueNumber]/layout.tsx`**: the sticky stage-tab `<nav>` gained
  `max-lg:flex-nowrap max-lg:overflow-x-auto` (single scrollable row below lg);
  each tab `<Link>` gained `shrink-0`.

### Task 2 — Functional/UX fixes

- **My Tasks** (`MyTasksScreen.tsx`): `MyTasksList` now groups its
  already-severity-sorted tasks into up to three `<section>`s — "Must fix · N"
  / "Review recommended · N" / "Information · N" — each header a single text
  node (no nested `<span>` reading exactly "Must fix", so the row-level
  `SeverityBadge`'s `getByText('Must fix')` stays unambiguous). Empty buckets
  omitted; row markup unchanged (extracted into `renderTask`).
- **Decision log consolidation**: removed `<DecisionLog>` from `LeadActions.tsx`
  and `BriefFieldStrengthen.tsx` (was mounted once per lead / once per Brief
  field — up to ~11 duplicate run-scoped logs on the Story page). Mounted
  exactly ONE `<DecisionLog runId={effectiveRunId} />` at the bottom of
  `StoryBriefScreen.tsx`'s main return, under a "Decision log" heading.
- **`HelpTip.tsx`**: popover now renders through `createPortal(document.body)`
  with `position: fixed`, positioned from the trigger's
  `getBoundingClientRect()` (default below, clamped 8px from viewport
  left/right, flips above when there's no room below), raised to `z-[60]`.
  Mounts the portal only after a client-side `mounted` effect fires (SSR-safe).
- **Table caps**: `RegistryTable.tsx` caps at latest 50 filtered rows;
  `IssueRevenueTable.tsx` caps at latest 24 issue rows (the Unattributed row
  stays unconditionally visible, outside the cap). Both add a "Show all (N)"
  toggle and a "showing latest N of M" note, mirroring `RunsTable.tsx`'s
  existing client-cap exemplar.

  redirect-only; no dedicated test file existed).
- **`convex/runs.ts`**: added `listRecentForWorkspace` (additive — same

  `startedAt desc`). `RunsTable.tsx` switched to it; `listForWorkspace` and
  its other subscribers (ReviewQueue, CostRollup, DriftStrip) are untouched.
- **Draft-stage preview fix** (`ReviewDeskRunView.tsx`, item 2g,
  user-reported): the `'iframe'` mode's mount wrapper changed from
  `min-h-[500px] flex-1` (never a definite height, so `PreviewIframe`'s

## Flex-Column Margin-Collapse Scan (item 1d)

Scanned the direct page roots that become flex-column items of `<main>`:

| Root | Structure | Margin-collapse risk |
|---|---|---|
| `MyTasksScreen.tsx` (default export) | single `<div className="flex flex-col gap-4">` | None — uses `gap-4`, no bare top/bottom margin on the root |
| `IssueWorkspaceLayout` / `FrameChrome` | single `<div className="min-h-full ... py-2">` | None — `py-2` is genuine padding, not a margin |
| `settings/page.tsx` | single `<div className="space-y-8">` | None — `space-y-*` uses `> * + *` margin-top selectors internal to the div, not a root-level margin |
| `finance/page.tsx` | single `<div className="space-y-4">` | None — same `space-y-*` pattern |
| `registry/page.tsx` | single `<div className="space-y-6">` | None — same `space-y-*` pattern |
| `run-monitor/layout.tsx` shell | single `<div className="flex min-h-0 flex-1 flex-col">` | None — flex container, margins between its own children don't collapse by CSS spec regardless |

Result: every scanned root is a single top-level element using `gap`/`padding`/
`space-y-*` for its own internal spacing; none relies on a bare top/bottom
margin on itself expecting to collapse with `<main>`'s box (which wouldn't
happen anyway once `<main>` became `flex flex-col` — flex items never
margin-collapse with their container or siblings). No fixes were needed here;
this was a verification pass only.
