# Quick 260717-41s: Make convex/charities.ts seedFromPublished idempotent Summary

Fixed `seedFromPublished`'s non-idempotent `timesFeatured` increment (which had inflated a live dev row to `33886`) by tallying per-dedupKey row occurrences in memory and SETting the counter to that tally instead of incrementing it on every call — with convex-test coverage that genuinely fails against the pre-fix code, and a backfill-script fix so the mutation actually receives one row per published issue instead of one row per unique name.

## What Was Built

**Task 1 — `convex/charities.ts` (`seedFromPublished`):** Rewrote the handler as two passes. Pass 1 tallies `rows` in memory into a `Map<dedupKey, {name, website?, sanityCharityId?, domain, count}>` (dedupKey = `name.trim().toLowerCase()|bareDomain(website)`, reusing the existing `bareDomain` helper), enriching missing `website`/`sanityCharityId` on repeat keys via `??=` so a sparse duplicate row can't erase a populated one. Pass 2 writes sequentially (same `by_workspace_dedupKey` index lookup, same sequential-for-loop shape/comment as before) — the ONLY semantic change is `timesFeatured: (existing.timesFeatured ?? 0) + 1` → `timesFeatured: seed.count`, and the insert path's hardcoded `1` → `seed.count`. Everything else (`requirePipelineSecret` first, `status: 'featured'`, `lastFeaturedAt: now`, the backfill-if-missing website/domain spreads, the sanityCharityId truthy-spread) is preserved exactly. `upsertFeatured` is byte-identical to before — not touched.

**Task 2 — convex-test coverage:** New `apps/dispatch-control/__tests__/seedFromPublishedIdempotent.test.ts` mirrors `convexAuthLockdown.test.ts`'s harness pattern exactly (literal `import.meta.glob`, `convexTest({schema, modules})`, `PIPELINE_CONVEX_SECRET` beforeEach/afterEach stub). Five tests:
1. Double-seed convergence — identical rows seeded twice yields `timesFeatured === 1` both times, exactly one row.
2. In-call multiplicity — same charity 3x in one `rows` array → `timesFeatured === 3`.
3. Fresh-insert multiplicity — 3 duplicate rows on an empty registry insert with `timesFeatured === 3`.
4. Convergence/self-heal — a pre-corrupted row (`timesFeatured: 33886`) converges to `1` on the next seed.
5. Guard — missing/wrong `pipelineSecret` still throws `Unauthorized`.

Registered in `vitest.config.ts`'s `environmentMatchGlobs` under `edge-runtime` (convex-test requirement), alongside the existing ~14 entries.

**Task 3 — `packages/pipeline/scripts/backfill_charity_registry.py`:** Removed the `seen: set[str]` name-lowercase dedup from `_normalise_rows` — the mutation's tally is only meaningful if row multiplicity (one row per published issue) survives to Convex; the old dedup collapsed every charity to exactly one row, which would have made every `seedFromPublished` tally compute `1` regardless of true issue count. Added `!(_id in path("drafts.**"))` to `_GROQ_FEATURED` — the script authenticates with `SANITY_API_TOKEN` so drafts are visible, and a `drafts.*` copy of a published issue also satisfies `status == "published"`; this was harmless while the old dedup masked it, but is now a real double-count risk. Updated prints/docstrings from "unique row(s)" language to "one row per published issue".
