<objective>
Make `convex/charities.ts` → `seedFromPublished` genuinely idempotent. It is documented as idempotent in three places but increments `timesFeatured` per row per call, so every re-run inflates the counter (live dev deployment shows `RIP Medical Debt` at `timesFeatured: 33886`, rendered by the Registry UI as "featured 33,886 times").

Fix: tally occurrences per `dedupKey` **across the input rows**, then **SET** `timesFeatured` to that tally instead of incrementing. Re-running with the same input converges to the same value and self-heals the corrupted row on the next backfill.

Purpose: the mutation's docstring contract ("idempotent") becomes true, and the Registry stops displaying a garbage number.
Output: fixed mutation + convex-test proving idempotency + backfill caller sending row multiplicity that makes the tally meaningful.
</objective>

The GROQ returns one row per published issue; the tally is only meaningful if that multiplicity survives to the mutation.

Change 1 — remove the name-dedup in `_normalise_rows`: drop the `seen: set[str]` / `key = name.lower()` / `if key in seen: continue` block. Keep the empty-name skip and the existing `seed_row` construction (name / website / `sanityCharityId = f"charity-{slug}"`) exactly as-is. Result: one seed row per published issue. Update the docstring — the mutation now DERIVES timesFeatured from row multiplicity, so deduping here would undercount. Note that same-name/different-website charities are correctly separated by the mutation's `name|domain` dedupKey, which the old name-only dedup silently collapsed.

Change 2 — exclude Sanity drafts from `_GROQ_FEATURED` (line 42-45). The script authenticates with `SANITY_API_TOKEN`, so drafts ARE visible; a `drafts.*` copy of a published issue also carries `status == "published"` and would now be counted a second time. This was harmless while the caller deduped by name — removing the dedup exposes it, so the two changes ship together. Add the standard idiom:
