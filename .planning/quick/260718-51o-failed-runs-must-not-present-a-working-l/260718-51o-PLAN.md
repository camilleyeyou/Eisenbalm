<objective>
A pipeline run that FAILED (e.g. Scout returned zero candidates) currently masquerades as a normal, reviewable in-progress issue: `deriveIssueStatus` returns `'needs-review'`, the workspace resumes on the Approval stage, and `approval/page.tsx` mounts `DecisionRail` — whose "Sign: Facts cleared" / "Sign: Sounds human" buttons can only ever 409 (`claims_not_signed_off` over 0 claims; the draft endpoint 409s `no_sanity_issue`). This is the exact dead-end class the project just spent Phase 33/34 eliminating.

Make `runStatus === 'failed'` a first-class TERMINAL state so a failed run stops advertising itself as reviewable, mirroring the existing first-class failed treatment in run-monitor's `RunDetail.tsx` (red badge + `errorMessage` + `RecoveryRail`).

Purpose: A failed run must show "this run failed — nothing to review, go re-run" instead of offering actions that cannot succeed.
Output: Failed-aware pure derivations (with RED→GREEN unit tests), the new `'failed'` IssueStatus value propagated to all three consumers (type-enforced), and a server-side terminal panel on the Approval route that links onward to the recovery rail.
</objective>
