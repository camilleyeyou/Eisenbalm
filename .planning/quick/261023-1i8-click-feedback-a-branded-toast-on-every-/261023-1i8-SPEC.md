# SPEC — Click feedback in dispatch-control: a toast on every action

Written 2026-10-23 for the GSD quick-task planner + executor. Treat it as
locked. User request, verbatim: "when we click buttons we should have
notification to let us know the click worked, for example when you click the
published button, it should at least show that it worked and the rest of the
buttons too".

## Diagnosis

`apps/dispatch-control` has no shared notification layer. Each action reports
its outcome differently or not at all:

- Home (`app/(editorial)/_components/IssueHome.tsx`): Publish only flips the
  button to busy and later changes the status word; Start, Release, Stop and
  Hold change state silently; Discard shows an inline "Discarding…" line.
  Errors appear as inline `role="alert"` text under the button.
- Section page: paragraph Save shows a small inline "Saved" for 3 s
  (`SectionArticle.tsx` → `ParagraphRow.tsx`); Rewrite shows an inline phase
  message (`RewriteThisPart.tsx`).
- Admin ("Behind the scenes"): most actions set a local `error` only; success is
  silent except `AutomationPanel` (3 s "saved" flag) and `PromptMarkerExport`
  (1.5 s "Copied").

The editor cannot tell whether a click registered. The fix is one branded toast
system mounted once, plus wiring at every data-changing button.

## Non-negotiables

- Design language: the 1c tokens in `app/globals.css` (`--color-card`,
  `--color-ink`, `--color-cobalt`, `--color-done`, `--color-problem`,
  `--font-ui`, `--font-body`), UI text 15–17 px, no mono-caps chips, plain
  words. Grandma-simple: one sentence, optionally one short second line.
- Copy must pass `EDITOR_BANNED_PATTERN` (`lib/editorState.ts`: no run/runs,
  trigger, pipeline, graph, DAG, drift, re-roll, calibrator, chronicler, agent(s),
  token(s), gate, interrupt, deterministic, awaiting-review, failed) and the
  admin `UI_JARGON` scan (`__tests__/helpers/jargonScan.ts`, same list plus
  "run detail"). Never say "failed" — say "didn't go through" / "didn't finish".
- Existing inline errors and inline statuses STAY. Toasts are added on top; they
  never replace an inline message a test asserts on.
- Existing tests must stay green unchanged, in particular
  `__tests__/IssueHome.test.tsx` (its slow-notice test does
  `screen.getByRole('status')` on a bare `<IssueHome />` — so toasts must render
  only inside the provider, and the hook must be a silent no-op without one),
  `editorCopy.test.tsx` (one h1, ≤1 `[data-primary]`, zero `[disabled]`
  controls on every screen — toasts must not add any of those),
  `adminPagesJargon.test.ts`.
- No new dependency. Hand-rolled provider, mirroring
  `components/ui/ConfirmDialog.tsx`'s createContext pattern.

## A. The toast layer — `components/ui/Toast.tsx` (new, `'use client'`)

```ts
export type ToastTone = 'done' | 'problem' | 'info'
export interface ToastInput { title: string; detail?: string; duration?: number }
export interface ToastApi {
  done: (title: string, detail?: string) => void
  problem: (title: string, detail?: string) => void
  info: (title: string, detail?: string) => void
}
export function ToastProvider({ children }: { children: ReactNode }): JSX.Element
export function useToast(): ToastApi
```

Behaviour:
- State: an array of `{ id, tone, title, detail, createdAt, duration }`. Max 3
  visible; pushing a 4th drops the oldest.
- Durations: `done`/`info` 5000 ms, `problem` 9000 ms. A hover or focus on a
  toast pauses its timer; leaving resumes it. Each toast has a 44×44 px close
  button with `aria-label="Dismiss"`.
- Dedup: an identical `tone+title` pushed within 1500 ms of an existing one is
  ignored (double-clicks and React strict-mode double effects).
- `useToast()` outside a provider returns stable no-op functions (does NOT
  throw). Inside, functions are stable (`useMemo`).
- Region markup: a fixed container `aria-live="polite"` (no role) at
  `bottom: 24px`, centered, `width: min(560px, calc(100% - 32px))`, `z-[80]`
  (above ConfirmDialog's `z-[70]`), `pointer-events-none` on the container and
  `pointer-events-auto` on each toast. Each toast: `role="status"` for
  done/info, `role="alert"` for problem.
- Toast look: `bg-[color:var(--color-card)]`, `border-2 border-[color:var(--color-ink)]`,
  a 6 px left bar in the tone colour (`--color-done` / `--color-problem` /
  `--color-cobalt`), padding 14–16 px, soft shadow, title in `--font-ui` 17 px
  semibold `--color-ink`, detail in `--font-body` 15 px `--color-ink-soft`.
  Enter animation: 160 ms fade+rise via a `toast-enter` keyframe added to
  `app/globals.css` next to `editor-pulse`, disabled under
  `@media (prefers-reduced-motion: reduce)`.
- Mount ONCE in `app/layout.tsx` (Server Component — keep it so): wrap
  `{children}` with `<ToastProvider>` inside `ConvexClientProvider`. That covers
  the editorial group, `/admin/*` and `/sign-in`.

Also export a `data-testid="toast"` on each toast root for tests.

## C. Wiring — editorial

Rule: every button that changes data or calls the server gets a `done` toast
on success and a `problem` toast on failure. Actions that take more than a
couple of seconds ALSO get an `info` toast the instant the click is accepted
(publish, start, stop, discard, rewrite). Pure UI toggles, filters, open/close,
cancel, and navigation links get nothing.

### C1. `IssueHome.tsx`
- `const toast = useToast()`.
- `publish`: `toast.info(COPY.toastPublishing)` right after `setPhase('publishing')`;
  on `!r.ok` → `toast.problem(COPY.toastPublishFailed, COPY.toastPublishFailedDetail)`
  (inline `actionError` stays). On success nothing yet — the existing effect
  that releases the latch when `footer.kind === 'published' && phase === 'publishing'`
  additionally calls `toast.done(COPY.toastPublished, COPY.toastPublishedDetail)`.
- `start-*`: `toast.info(COPY.toastStarting)` on click; `toast.done(COPY.toastStarted)`
  after `triggerRun` resolves; `toast.problem(COPY.toastStartFailed)` in catch.
- `release`: `toast.done(COPY.toastReleased, COPY.toastReleasedDetail)` /
  `toast.problem(COPY.toastTryAgain)`.
- `stop-stuck` and `stopRun`: `toast.info(COPY.toastStopping)` after the confirm
  is accepted; `toast.done(COPY.toastStopped)` on resolve; `toast.problem(COPY.toastTryAgain)`.
- `onHold`: `toast.done(COPY.toastHeld, COPY.toastHeldDetail)` / `toast.problem(COPY.toastTryAgain)`.
- `discardIssue`: `toast.info(COPY.toastDiscarding)` on click; on resolve
  `toast.done(COPY.toastDiscarded, COPY.toastDiscardedDetail)` (when
  `discardRequested`, the done toast fires when `vm.state` becomes `'stopped'`
  in the existing effect, so it reflects the real completion); catch →
  `toast.problem(<the same message chosen for discardError>)`.
- Replace `{issue}` with `issueLabel` everywhere.

### C2. `s/[section]/_components/SectionArticle.tsx`
- After a successful `patchSection`/`patchBonus` + `onSaved()`:
  `toast.done(COPY.toastSaved, COPY.toastSavedDetail)`. In the catch that sets
  `COPY.saveFailed`: `toast.problem(COPY.saveFailed)`. Inline "Saved" stays.

### C3. `s/[section]/_components/RewriteThisPart.tsx`
- `rewrite()`: `toast.info(COPY.toastRewriting)` at start;
  `toast.done(COPY.toastRewritten, COPY.toastRewrittenDetail)` when phase
  becomes `choosing`; `toast.problem(COPY.toastRewriteFailed)` on the rerollAgent
  catch.
- "Keep this version" click → `toast.done(COPY.toastKept)`.
- `goBack()` success → `toast.done(COPY.toastWentBack)`; catch →
  `toast.problem(COPY.saveFailed)`.

### C4. `HoldStopFooter.tsx` / `DiscardIssueControl.tsx`
No change needed if the toasts live in the IssueHome handlers (they do). Do not
add toasts for the confirm dialog's Cancel.

## D. Wiring — admin ("Behind the scenes")

Same rule. Strings live inline in each component as plain words (they are not
editor-facing COPY). Each line = success / failure:

| Component | Action | done | problem |
|---|---|---|---|
| `agents/_components/PromptSaveDialog.tsx` | save version | `Saved as v{N}.` (use `nextVersion`; if null, `Saved.`) | `Could not save. Try again.` (inline error stays) |
| `agents/_components/VersionHistoryPanel.tsx` | activate / override | `v{N} is now in use.` | blocked → `v{N} was not switched on.` with the blocked reason as detail; thrown error → `Could not switch versions. Try again.` |
| `agents/_components/PromptMarkerExport.tsx` | copy | `Copied.` | `Copy didn't work. Select the text instead.` |
| `agents/_components/TestRunPanel.tsx` | Run / Compare | `Test finished.` / `Comparison finished.` | `The test didn't finish.` / `The comparison didn't finish.` |
| `agents/_components/EvalDrawer.tsx` | run quality tests | `Quality tests finished.` (after the loop) | `Some quality tests didn't finish.` if any row ended in error |
| `automation/_components/AutomationPanel.tsx` | toggle schedule | `Schedule switched on.` / `Schedule switched off.` | `Could not change the schedule. Try again.` (currently only console.error — add the toast) |
| `automation/_components/AutomationPanel.tsx` | save schedule | `Schedule saved.` | `Could not save the schedule. Try again.` |
| `automation/_components/AutoPublishToggle.tsx` | enable / disable | `Publish by itself is on.` / `Publish by itself is off.` | the existing error text |

| `charities/_components/RegistryTable.tsx` | do-not-use / allow again | `{name} marked do not use.` / `{name} can be chosen again.` | existing text |
| `charities/_components/AddCharityDialog.tsx` | add | `{name} added to the list.` | existing text |
| `charities/_components/AddCorrectionDialog.tsx` | save correction | `Correction saved.` | existing text |
