# Phase quick-260621-d31 Plan 01: Fix per-agent OpenRouter cost/token capture Summary

Re-armed the inert per-run AI cost cap by making `acomplete()` record REAL OpenRouter token counts and authoritative USD (from OpenRouter usage accounting), replacing the structured-output path's hardcoded zeros and the plain-text path's phantom `input_cost`/`output_cost` math.

## What Changed

**`lib/openrouter_client.py`:**
- `_build_chat_model`: `extra_body` now seeds `{"usage": {"include": True}}` (OpenRouter usage accounting) before merging the Anthropic provider pin, so `usage.cost` surfaces in `response_metadata["token_usage"]["cost"]`.
- New `_usage_from_message(msg, fallback_model)` helper: reads `usage_metadata.input_tokens/output_tokens` for tokens, `response_metadata["token_usage"]["cost"]` for USD (None → 0.0 defensive), and `model_name`→`model`→pin for resolved model. Used by BOTH paths.
- Structured path: `with_structured_output(response_format, include_raw=True)` returns `{"raw","parsed","parsing_error"}`. A schema miss no longer raises — it surfaces as `parsed is None`, which triggers exactly one corrective retry; a second miss propagates `parsing_error` (or `RuntimeError`). The `try/except` is retained ONLY for transport errors from `ainvoke`. Cost is recorded exactly once from the final/successful `raw`.
- Plain-text path: collapses to the same `_usage_from_message` helper; old broken `usage["input_cost"]`/`["output_cost"]` arithmetic removed.
- Stub-mode short-circuit, `record_model_version`, `acomplete`'s public signature, and the 4-key usage dict shape (`tokens_in, tokens_out, usd, resolved_model`) are all unchanged.

**`tests/lib/test_openrouter_cost_capture.py` (new):** 5 tests patching `_build_chat_model` inside `openrouter_client` to drive `acomplete` against a fake `AIMessage`.

## USD-Capture Approach (as required)

USD is captured via **OpenRouter usage accounting**: `_build_chat_model` opts in with `extra_body usage={"include": True}`, and `langchain-openai==1.2.1` passes the raw `usage` object through into `response_metadata["token_usage"]`, where `_usage_from_message` reads `["cost"]` as the authoritative charged dollar amount. No local price table was introduced. When `cost` is absent (provider didn't echo it), USD records `0.0` (conservative — the cap is never falsely tripped).

## No Double-Counting (confirmed)

`record_cost` is additive over `(run_id, agent_name)`. The split is non-overlapping and preserved:
- `acomplete()` contributes `tokens_in/tokens_out/usd` with `duration_ms=0` (default) — recorded exactly ONCE per call, from the single final `raw` (the retry test asserts cost comes from the 2nd raw only, not the failed attempt).
- `@agent_node` (`_wrapper.py`, read-only this task) contributes `duration_ms` only with 0 tokens / $0.

The wrapper was not touched, so the two recorders remain on disjoint fields — no double-count.
