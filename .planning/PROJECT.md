# The Eisenbalm Dispatch

## What This Is

A weekly AI-generated editorial website that spotlights an obscure charity each week, sells one product (Jesse A. Eisenbalm lip balm), and donates 100% of proceeds to the featured charity. Editorial content is produced by an 18-node LangGraph pipeline (LLM agents + deterministic code gates); a human editor (Andrew) reviews and publishes via the Dispatch Control operator console. The site is a destination — it should feel like a magazine that happens to sell one product, not a newsletter.

## Core Value

Every Thursday, ship a complete, on-voice issue: one obscure charity, eight original sections (origin story, problem, founder bio, case study, game, bonus, deliberation, podcast), and a working shop callout — published only after Andrew's manual review.

## Current Milestone: v4.0 Dispatch Control v3 — The Editorial Workspace

**Status: 🚧 IN PROGRESS** — started 2026-07-14. Phases 40–50 (numbering continues from v3.0, which ended at 39). Prior milestone v3.0 (Dispatch Control v2, phases 30–39) shipped 2026-07-10 and is the substrate; its record lives in `MILESTONES.md` + `milestones/v3.0-*.md`.

**Goal:** The console stops being a set of desks that mirror the pipeline and becomes an editorial product with an **issue** at its center. The machine retreats behind a "System Workbench" the operator visits only when something broke or they want to make an agent better. **The editor never "triggers a pipeline."**

**Binding spec:** `docs/design/dispatch-control-v3/` — `Dispatch Control v3 - Annotations.md` (semantics, states, permissions, nomenclature), `DERIVED-STATE-CONTRACT.md` (state machine, inspector artifact shape, role gating, run-step naming), `README.md` (decisions + color semantics). The prototype `Dispatch Control v3.dc.html` is the visual spec.

**Target features (foundation-first — a working Issue Workspace is demoable by Phase 41):**
- **Issue as first-class entity** — console routing today is run-keyed (`/review-desk/[runId]`); v3 inverts this so runs become historical records *under* an issue. Issues home: in-progress card with the 5-stage strip, scheduled slot + Calibrator note, held issues with reason/who/when, recently published with verification record. Held state + required reason + Reopen.
- **One Issue Workspace** replacing three nav items — stage tabs 1–5 with live status marks, persistent issue outline (5-state legend), collapsible context panel, persistent controls (save state, Ask an agent, Decision log, Hold issue). Signal Desk → Stage 1; Review Desk galley → Stage 2 Draft; Voice Pass → Stage 4; decision rail + publish gate → Stage 5 Approval. Stages 2/4/5 are **recomposition** over shipped endpoints (content-patch, sign-offs, provenance, span resolver).
- **Stage 3 Fact Check** — the only genuinely new stage. Affirmative summary (checked X of Y · must fix · conflicts · checks not run · changed since check · last verified; **"blank never means verified"**), filters, claim table, and a claim-detail provenance card reused in Draft, Approval, and the inspector. Requires a new `importance` field (Load-bearing / Supporting / Incidental) emitted by the Researcher.
- **My Tasks** — a **derived projection** over open claims / open findings / missing sign-offs. Not a new table (see `DERIVED-STATE-CONTRACT.md` §2).
- **Inspect how this was made** — one universal 7-tab panel, 6 artifact types, reachable from 6 places; anchors to *steps*, not spans (`sectionName → writer → agent_runs`). The Inputs tab's **missing-expected-input diff** (declared template vars minus keys actually supplied at run time) turns a bad sentence into a prompt fix — the highest-leverage item in the design.
- **Ask agent to revise / Ask agent for better evidence** — agent revision as an editing verb everywhere. Direction chips (never a bare "Regenerate"), comparison card naming the claim delta, then Apply / Edit before applying / Try another / Discard. New span-scoped revision endpoints; needs a per-issue cost guard.
- **Signal Editor agent + verify_candidates gate** — the v3.0 deferral comes due: Stage 1 is built on story leads and a verification record that do not exist today. Pipeline grows 18 → 20 nodes.
- **Stage 1 Story & Brief** — 3–5 dated story leads (peg, reader energy, angle, brand risk, confidence; Require this lead / Remove — add reason), organization options nested under the chosen lead with their verification record and an always-visible main concern, plus an editable **Brief** (premise, peg, central claim, reader effect, known risks, voice intention) that the writers draft *from*.
- **Start from my brief** — a real second pipeline entry point: human supplies premise/peg/organization, Scout + Gate 1 are skipped, the run enters at the Researcher.
- **Roles** — Editor-in-chief vs Collaborator, gating exactly 6 actions (apply revision, confirm evidence replacement, approve voice, publish, make instruction active, mark Do not use). Locked controls **render with an explanation**, never hidden.
- **Workbench rename + nomenclature pass** — Run Monitor → Run Details (action-named steps, "historical record" framing when idle, failed-run recovery rail), Prompt Lab → Agent Instructions (+ "why this draft exists" bridge back to the output that motivated it), Eval Center → Quality Tests (shadow run → "Preview next run"), Registry → Editorial Memory. Wide but shallow: the v3 Workbench spec is ~80% already shipped.

**Locked decisions (2026-07-14):**
- **"Start from my brief" is in scope** as a real pipeline entry point, not a stub — shipping a dead button in the primary CTA is worse than the phase it costs.
- **Publish drops typed confirmation** (reverses Phase 34) — exact preview + one click. The gate is the safety: Must fix = 0 ∧ Fact Check complete ∧ Voice approved current. Typed confirmation survives **only** for Mark Do-not-use. "Routine weekly approval is deliberately not scary."
- **Claim importance is emitted by the Researcher** — one field on each claim. Not a new judge call, not derived post-hoc.
- **"Changed since check" is a block-level touched-counter**, not a re-verification requirement — matching the prototype, where an edit whose replacement text is *itself sourced* still increments the counter.
- **Sign-off revocation stays as Phase 34 built it.** The prototype does not revoke voice approval when a revision is applied, contradicting its own copy. That is a prototype bug. Port the sentence, not the wiring.
- **Signal Editor + verify_candidates are in scope** — Stage 1 without them is a restyle of the old Signal Desk, and the design's whole trust story rests on the verification record.

**Reconciliation facts the roadmap must honor (re-verified in code 2026-07-14):**
- **DO NOT REBUILD the design system.** The 1c tokens shipped in Phase 30 **are** the v3 design system — verified identical against `apps/dispatch-control/app/globals.css` (Newsreader/Lora/Space Grotesk/IBM Plex Mono; ink `#17140e`, paper `#e9eaec`, cobalt `#253ad4`, vermilion `#e8471d`, marigold `#f2b01e`, green `#148a52`; `--radius: 0`). Zero token work. The older v2-brief palette (Cormorant, rust `#C2502A`, gold `#CDA434`, warm paper) is dead — do not reintroduce it.
- **DO NOT REBUILD the publish gate.** The Phase 34 two-sign-off gate (`sign_offs`: `facts-cleared` + `sounds-human`, revoked on content mutation) is *exactly* v3's `ready = factDone && voiceDone`. Reuse it; only the typed-confirmation step is removed.
- **DO NOT REBUILD the eval commit gate.** Phase 38's activate gate (target-up / no-regression + logged override-with-reason) is *exactly* v3's "Make active — with reviewed regression."
- **The pipeline is 18 nodes today** (calibrator → scout → advocate → editor_gate_1 [interrupt] → chronicler → researcher → verify_research [gate] → 7 parallel writers → validate_sections [gate] → qa → editor_final → publisher). There is **no Signal Editor and no verify-candidates gate** — this milestone adds both (→ 20 nodes). The prototype's Run Details step list is aspirational on exactly these two points; every other step maps to a real node.
- **Provenance substrate exists** (Phase 35): `claim_checks` carries `claimId` / `sourceUrl` / `retrievedAt` / `sectionName`, and writers emit `claimSpans`. Fact Check builds on this; the only new field is `importance`.
- **Pause/notify/resume exists:** `editor_gate_1` uses LangGraph `interrupt()` + AsyncPostgresSaver (Railway Postgres); resume via `POST /run/{run_id}/resume`. This is what "⏸ Paused for you" renders.
- **Write boundary holds:** every console content mutation goes dashboard → pipeline API → Sanity, logged to `audit_log`. The new revision endpoints must respect it (an EDT-05 source-scan test proves zero direct Sanity writes).
- **RBAC is unbuilt:** `convex/schema.ts` `users.role` is an optional string with a "deferred to Phase 28" comment. Phase 28 was absorbed; roles land this milestone.
- Content ownership today: Sanity (editorial content, publish trigger of record) / Convex (27 tables) / Railway Postgres (checkpointer + webhook idempotency).

## Context

**Brand voice (fragile, voice-critical):** Jesse's voice is dry, precise, absurdly serious. No winking. No irony signaling. The joke is that everything is played completely straight. Charities are treated with Fortune 500 gravity. The editorial question is always "Why do you deserve to exist?" — answered without sentiment. Voice drift is the highest-impact failure mode (the brand collapses), and the QA agent is the only automated guardrail.

- Editor gate 1 (in-pipeline) — pauses LangGraph if no winner can be selected; surfaces to Andrew via Convex run state.
- Andrew gate (terminal) — Sanity Studio review before publish. Single point of human control over what ships.

## Constraints

- **Tech stack**: Next.js 14+ (App Router) on Vercel · Sanity v3 · FastAPI on Railway · LangGraph · OpenRouter · Supabase · Convex · Stripe · WeasyPrint or Playwright — locked by brief, do not substitute
- **Repository**: monorepo (`apps/web`, `apps/studio`, `packages/pipeline`, `packages/shared`, plus existing `convex/` and `schemas/`) — to be scaffolded in Phase 1
- **Cadence**: weekly issue. Pipeline must complete + Andrew must review + Publisher must deploy within a Thu→Thu window. Slow pipelines or Andrew bottlenecks break the format.
- **Voice**: Jesse's voice is non-negotiable. Voice drift = brand failure. QA + Editor Final are the automated guards; Andrew is the manual guard.
- **AI cost**: 9 agents per run × multiple OpenRouter calls + web search. Per-run cost containment matters.
- **Security**: Game agent emits HTML/JS rendered inside `iframe srcdoc sandbox="allow-scripts"` — must be airtight. Theme injects CSS variables — must validate hex colors and font names.
- **Andrew is single-threaded**: no backup reviewer specified. If Andrew is offline, no issue ships that week.
- **Stripe is custom**: no Shopify, no Commerce.js, no urgency mechanics. Webhook signature verification + idempotency required.
