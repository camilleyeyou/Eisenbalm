Design Audit Dispatch Control · v1 → v2

Making one editor
operate like a masthead

A deep read of the operator console — where v1 leaves the editor stranded, and where the v2 plan is right, risky, or incomplete.

The two questions everything answers to

The product's promise is not "a dashboard for a pipeline." It is: turn one person into a whole editorial team, and make sure the result never reads like a machine wrote it. Every surface should be judged against two questions.

01

Can one person confidently ship in minutes — knowing what's blocking, sourced, and decided?

02

Does the tool actively help kill AI-slop — or only detect it, and leave the editor to notice?

v1 answers neither. The v2 brief answers the first well and the second only halfway. That gap is the through-line of this audit.

01 — Where v1 strands the editor

A builder's tool wearing an editor's job.

v1 is CRUD over prompts and runs plus a /graph DAG. Each of these is the plumbing showing through the floor — the editor manages the machine instead of the magazine.

01
No galley

Review happens against JSON artifacts and run logs. There is nowhere to read the piece as the reader will — which guarantees slop ships, because slop is a reading experience, not a field value.

02
Provenance is invisible

Nothing shows which claims the Researcher sourced and which it invented. Trust is all-or-nothing: believe the whole issue, or re-check it by hand.

03
Publish isn't gated by editorial state

The DAG can complete with open errors and still be publishable. Nothing structurally stands between a flagged issue and the reader.

04
Prompt edits are unsafe

Improving a prompt means editing text and gambling on a paid, live run to see if it helped. No preview, no eval, no scoreboard — so prompts calcify.

05
The graph shows topology, not meaning

/graph proves the pipeline ran. It cannot show what each agent decided or why. The editor sees a machine's shape, never its judgment.

06
No intervention affordances

No approve / reject, no send-back-a-step, no "this is waiting for you." Intervention is possible only by editing the underlying data — the very JSON-first failure the product exists to avoid.

07
No memory in view

Repetition across weeks, corrections, and coverage are invisible, so the system can't visibly learn — and the editor can't tell if this week rhymes with last.

02 — Where the v2 plan is right

It turns every one of those gaps into a surface.

Credit where due — the brief's core moves are the correct ones, and they map almost one-to-one onto the failures above:

  • ✓Galley-first review — the issue is finally the object of the UI, read as the reader will see it. Slop is a reading experience; you can only catch it by reading.
  • ✓Provenance as a component — one "sourced claim" affordance everywhere, with unsourced as a visible state. Trust stops being all-or-nothing.
  • ✓Gated publish + blocking list — you can't ship over an open error. The decision is a checklist, not a vibe.
  • ✓Prompt Lab with eval scoreboard — edit → eval → commit/rollback without gambling a paid run. The single biggest lever on quality.
  • ✓Coverage memory + append-only corrections — the system learns in front of you instead of repeating itself.

03 — Where the v2 plan is risky or incomplete

Six places the plan will bite.

None cosmetic. Each is a spot where the current framing quietly works against one of the two questions above.

R1 "Silence means verified" is a trust bug, not a feature

The brief wants absence-of-flags to read as "verified." But absence is ambiguous: a check that passed and a check that never ran both produce silence. Under weekly load the editor learns to trust the quiet — and the one week a verifier crashes, an unchecked issue ships looking spotless.

Fix  Verification must be asserted, not implied. "11/11 claims sourced · checked 2m ago," never blank. Any check that didn't run is a first-class amber state. Draw the positive checkmark harder than the error.

R2 De-slopping is the product, but it's modeled as one QA axis

The single thing the human uniquely does — make it not sound like AI — is buried as a "machine-tells" count beside gate-integrity and fact-trace. That's backwards. Detection is not the craft act of rewriting.

Fix  Elevate it to its own step — a Voice Pass mode: read the piece clean, machine-tells and voice violations lit inline, one-keystroke rewrites, and a "sounds human" sign-off separate from "facts check out." Arguably the most important screen in the tool.

R3 The 5-minute review fights its own cognitive load

Galley + five rail modules + inline popovers + provenance highlights is a lot to land in five minutes. With no triage, the editor reads everything and it takes twenty.

Fix  Blockers-first. The default view is the decision, collapsed. The galley is where you go to resolve a specific flag — not the first wall you scan. Progressive disclosure, not everything-at-once.

R4 Unsourced-everywhere invites alarm fatigue

If provenance highlighting lights a dozen pale-rust spans, the signal dies and the editor tunes it out — the opposite of the intent.

Fix  Aggregate first ("3 unsourced claims → jump") and tier by stakes. A load-bearing statistic with no source is an error; an unsourced color detail is info. Not every claim carries equal risk.

R5 Commit-gating can deadlock; approval gates invite rubber-stamping

"No regressions or you can't commit" sounds safe, but every real edit regresses something trivial — so the gate becomes a wall or noise. Symmetrically, an approve button hit every week rots into a reflex.

Fix  Allow human override-with-reason (logged), and spend attention where it matters — brand-risk, low-confidence, and overruled decisions get typed confirmation; the safe 90% is one click. The tool should decide what's worth your eyes.

R6 Async intervention has no home

Agents pausing for human input is right — but Andrew isn't watching the run live. When he's in the Prompt Lab, where does "the pipeline is waiting for you" appear?

Fix  A cross-cutting "Awaiting you" inbox in the header — the one place that answers "what needs me right now" across every issue and stage. Without it, interrupts are visible only if you happen to be on the right screen.

04 — What I'd add

Five moves that close the gap.

1
An "Awaiting you" inbox

One header-level queue of everything blocked on a human, across issues and stages. Closes R6 and makes the whole async model legible.

2
A dedicated Voice Pass step

The de-slop line-edit as a first-class mode with its own sign-off, distinct from factual clearance. Closes R2 — the product's actual promise.

3
Affirmative verification state everywhere

Every factual surface reads sourced ✓ or unsourced — never blank. "Checked" is drawn louder than "error." Closes R1.

4
A confidence-driven attention model

The tool decides what to make you look at: high-risk and low-confidence items demand engagement; routine items collapse to one click. Closes R3 and R5.

5
One provenance component, tiered

A single sourced-claim affordance reused in galley, cards, and dossiers, with severity tiers and an aggregate count. Closes R4 and keeps the system coherent.

05 — Open questions for you

Live or forensic?

Is Andrew ever watching a run in real time, or always reviewing after it finishes? Decides whether Run Monitor is a live console or a forensic record.

Collaborator reach

Can the read-mostly collaborator triage the inbox and clear non-blocking flags, or strictly read-only? Changes whether one person is truly alone.

Seven writers, or one role?

Does the editor's view need all seven section writers as distinct nodes, or is that a builder's concern that should collapse in the review UI?

Is 5 minutes the goal or the ceiling?

A target and a hard constraint imply different amounts of forced triage and progressive disclosure.

Does "sounds human" get its own sign-off?

Separating "publishable" from "doesn't read like AI" is the crux of R2 — worth deciding before the Review Desk hardens.
